# P1.1 — OpenFGA Infrastructure + Authorization Schema v1

## Purpose

Ship the authorization-engine foundation: OpenFGA running locally as part of
`make dev`, a typed Rust representation of the authorization schema, and an
idempotent bootstrap binary that creates the OpenFGA store and applies the
model on every fresh stack.

End state:

- `docker-compose.yml` brings up OpenFGA v1.8 backed by a dedicated logical
  Postgres database (`openfga`) on the existing `postgres` service.
- `make dev` boots OpenFGA by default; `MOA_SKIP_FGA=1 make dev` opts out.
- `make fga-install` installs the `fga` CLI for local schema work.
- New crate `moa-authz-schema`: typed `TupleKey`, `ObjectType`, `Relation`,
  `UserType` newtypes plus the schema v1 DSL as a `&'static str` constant.
- New crate `moa-fga-bootstrap` (binary): creates the OpenFGA store
  idempotently, applies the v1 model, performs three smoke checks
  (`Check`/`ListObjects`/`BatchCheck`), writes resolved IDs to `.env.fga`
  for shell sourcing.
- Live integration tests `#[ignore]`-gated behind
  `MOA_RUN_LIVE_OPENFGA_TESTS=1` per `AGENTS.md` rules.
- `cargo run -p moa-fga-bootstrap` succeeds on a fresh stack and again on a
  re-run (idempotency is the acceptance bar, not a nice-to-have).

This prompt does not implement the FGA client wrapper, outbox, or any handler
authz checks — those land in P1.2 and P1.4.

## Prerequisites

- P1.0 merged. ADR-0002 is canonical.
- `main` checked out at the merge of P1.0.
- Docker and Docker Compose v2 available locally.
- Go 1.21+ installed (needed to install the `fga` CLI in Step 1).

## Steps

### 1. Add `openfga` database initialization

OpenFGA needs its own Postgres database. The existing `postgres` service
already runs PG17 with extensions; add a logical database for OpenFGA.

Create `docker/postgres/init/002-create-openfga-db.sql`:

```sql
-- Create the OpenFGA database if it does not already exist.
-- Postgres init scripts run only on first volume initialization; this is
-- intentionally idempotent for that boundary.
SELECT 'CREATE DATABASE openfga OWNER moa_owner'
WHERE NOT EXISTS (SELECT FROM pg_database WHERE datname = 'openfga')\gexec
```

This runs once on first stack boot. For re-runs against an existing volume,
the `openfga-db-init` sidecar (Step 2) ensures the database exists
idempotently.

### 2. Add `openfga-db-init`, `openfga-migrate`, and `openfga` services

Extend `docker-compose.yml`. Place the new services after the `postgres`
block and before `moa-orchestrator` so the dependency graph reads
top-to-bottom.

```yaml
  openfga-db-init:
    image: postgres:17-alpine
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      PGPASSWORD: ${POSTGRES_PASSWORD:-dev}
    entrypoint:
      - sh
      - -c
      - |
        set -e
        psql -h postgres -U moa_owner -d postgres -tAc \
          "SELECT 1 FROM pg_database WHERE datname='openfga'" \
        | grep -q 1 || \
          psql -h postgres -U moa_owner -d postgres \
          -c "CREATE DATABASE openfga OWNER moa_owner"
        echo "openfga db ready"
    restart: "no"

  openfga-migrate:
    image: openfga/openfga:v1.8.16
    depends_on:
      openfga-db-init:
        condition: service_completed_successfully
    command: ["migrate"]
    environment:
      OPENFGA_DATASTORE_ENGINE: postgres
      OPENFGA_DATASTORE_URI: postgres://moa_owner:${POSTGRES_PASSWORD:-dev}@postgres:5432/openfga?sslmode=disable
    restart: "no"

  openfga:
    image: openfga/openfga:v1.8.16
    depends_on:
      openfga-migrate:
        condition: service_completed_successfully
    command: ["run"]
    environment:
      OPENFGA_DATASTORE_ENGINE: postgres
      OPENFGA_DATASTORE_URI: postgres://moa_owner:${POSTGRES_PASSWORD:-dev}@postgres:5432/openfga?sslmode=disable
      OPENFGA_AUTHN_METHOD: preshared
      OPENFGA_AUTHN_PRESHARED_KEYS: ${MOA_OPENFGA_PRESHARED_KEY:-localdev-preshared-key-do-not-use-in-prod}
      OPENFGA_LOG_FORMAT: json
      OPENFGA_PLAYGROUND_ENABLED: "true"
    ports:
      - "8081:8080"   # HTTP API
      - "8082:8081"   # gRPC API
      - "3000:3000"   # Playground UI
    healthcheck:
      test: ["CMD", "/openfga", "healthcheck"]
      interval: 5s
      timeout: 2s
      retries: 20
    restart: unless-stopped
```

Notes on the wiring:

- `openfga-db-init` is the runtime equivalent of the init script: ensures the
  `openfga` database exists even on stacks that were initialized before this
  prompt landed.
- `openfga-migrate` is a `restart: "no"` sidecar; `condition:
  service_completed_successfully` blocks the `openfga` service until the
  schema is current.
- Port mapping: external `8081` → internal `8080` (HTTP), external `8082` →
  internal `8081` (gRPC), external `3000` → internal `3000` (Playground).
  The HTTP API on `8081` is what `moa-fga-bootstrap` and `moa-authz` will
  talk to.
- The `OPENFGA_AUTHN_PRESHARED_KEYS` default is a clearly-marked dev value.
  Production deployments must override via the same env var.
- The Playground is enabled in dev for schema iteration. P1.10 / production
  manifests will disable it.

### 3. Gate FGA behind `MOA_SKIP_FGA` (escape hatch only)

Per ADR-0002, OpenFGA boots by default. The only opt-out is the
`MOA_SKIP_FGA` env var, which is *not* a compose profile (no `--profile`
required) — it works by short-circuiting the services in the Makefile.

Update `Makefile`. Find the existing `dev` target and replace it with:

```make
.PHONY: dev
dev:
ifeq ($(MOA_SKIP_FGA),1)
	@echo ">> MOA_SKIP_FGA=1 set; bringing up stack WITHOUT OpenFGA"
	docker compose up -d postgres restate restate-register moa-orchestrator moa-pii-service moa-audit-shipper
else
	@echo ">> bringing up full stack with OpenFGA (default)"
	docker compose up -d
	@$(MAKE) fga-bootstrap
endif
```

Add a `fga-bootstrap` target that runs the new binary and exports IDs:

```make
.PHONY: fga-bootstrap
fga-bootstrap:
	@echo ">> waiting for OpenFGA"
	@./scripts/wait-for-fga.sh
	@echo ">> running moa-fga-bootstrap"
	@MOA_OPENFGA_URL=$${MOA_OPENFGA_URL:-http://localhost:8081} \
	 MOA_OPENFGA_PRESHARED_KEY=$${MOA_OPENFGA_PRESHARED_KEY:-localdev-preshared-key-do-not-use-in-prod} \
	 cargo run -q -p moa-fga-bootstrap
	@echo ">> store/model IDs written to .env.fga"
```

Add an `fga-install` target for the CLI:

```make
.PHONY: fga-install
fga-install:
	@echo ">> installing fga CLI"
	go install github.com/openfga/cli/cmd/fga@latest
	@echo ">> done; ensure \$$GOPATH/bin (or \$$HOME/go/bin) is on PATH"
```

Create `scripts/wait-for-fga.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

URL="${MOA_OPENFGA_URL:-http://localhost:8081}"
DEADLINE=$((SECONDS + 60))

echo "waiting for ${URL}/healthz ..."
while [ $SECONDS -lt $DEADLINE ]; do
  if curl -fsS "${URL}/healthz" > /dev/null 2>&1; then
    echo "openfga ready"
    exit 0
  fi
  sleep 1
done

echo "openfga did not become healthy within 60s" >&2
exit 1
```

`chmod +x scripts/wait-for-fga.sh`.

```rust
//! Authorization schema for MOA.
//!
//! This crate is the *single source of truth* for object types, relations,
//! and the OpenFGA model DSL. Other crates depend on this for compile-time
//! checked tuple construction.
//!
//! Schema versioning is append-only: schema changes write a new model id;
//! old tuples remain valid under the old model. See `MODEL_VERSION`.

pub mod tuple;

pub use tuple::{ObjectType, Relation, TupleKey, UserType};

/// The OpenFGA model DSL for schema v1. Authoritative.
///
/// This string is what `moa-fga-bootstrap` ships to OpenFGA via
/// `WriteAuthorizationModel`. It is checked into version control because the
/// schema is part of the security contract, not configuration.
pub const SCHEMA_V1_DSL: &str = include_str!("schema_v1.fga");

/// Logical version of the schema. Incremented on any change that adds, removes,
/// or restructures relations. Used in outbox idempotency keys so a tuple
/// written under v1 cannot be silently re-applied under v2.
pub const MODEL_VERSION: u32 = 1;
```

```rust
use uuid::Uuid;

/// The full enumeration of object types in schema v1. Stringly typed at the
/// FGA wire boundary, statically typed in Rust.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum ObjectType {
    Tenant,
    Workspace,
    Session,
    KnowledgeBase,
    Document,
    ApiKey,
    AgentTemplate,
    Agent,
}

impl fmt::Display for ObjectType {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let s = match self {
            ObjectType::Tenant => "tenant",
            ObjectType::Workspace => "workspace",
            ObjectType::Session => "session",
            ObjectType::KnowledgeBase => "knowledge_base",
            ObjectType::Document => "document",
            ObjectType::ApiKey => "api_key",
            ObjectType::AgentTemplate => "agent_template",
            ObjectType::Agent => "agent",
        };
        f.write_str(s)
    }
}

/// Subject types (the "user" side of a tuple).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum UserType {
    User,
    Agent,
    ApiKey,
}

impl fmt::Display for UserType {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let s = match self {
            UserType::User => "user",
            UserType::Agent => "agent",
            UserType::ApiKey => "api_key",

/// Relations defined in schema v1. Tied to ObjectType by convention; the
/// caller is responsible for using a relation that actually exists on the
/// target type. We enforce this at runtime in `moa-authz`; making it fully
/// type-safe would require a per-type enum and is deferred.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum Relation {
    Member,
    Admin,
    BillingAdmin,
    Editor,
    Owner,
    Participant,
    Reader,
    Writer,
    Creator,
    Operator,
    CanActAs,
    Tenant,
    Workspace,
    KnowledgeBase,
    Principal,
}

impl fmt::Display for Relation {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let s = match self {
            Relation::Member => "member",
            Relation::Admin => "admin",
            Relation::BillingAdmin => "billing_admin",
            Relation::Editor => "editor",
            Relation::Owner => "owner",
            Relation::Participant => "participant",
            Relation::Reader => "reader",
            Relation::Writer => "writer",
            Relation::Creator => "creator",
            Relation::Operator => "operator",
            Relation::CanActAs => "can_act_as",
            Relation::Tenant => "tenant",
            Relation::Workspace => "workspace",
            Relation::KnowledgeBase => "knowledge_base",
            Relation::Principal => "principal",
        };
        f.write_str(s)
    }
}

/// A fully-qualified OpenFGA tuple: subject (user_type, user_id) related to
/// (object_type, object_id) by `relation`.
///
/// `to_wire()` produces the JSON shape OpenFGA's `Write` API expects.
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct TupleKey {
    pub user_type: UserType,
    pub user_id: Uuid,
    pub relation: Relation,
    pub object_type: ObjectType,
    pub object_id: Uuid,
}

impl TupleKey {
    pub fn new(
        user_type: UserType,
        user_id: Uuid,
        relation: Relation,
        object_type: ObjectType,
        object_id: Uuid,
    ) -> Self {
        Self {
            user_type,
            user_id,
            relation,
            object_type,
            object_id,
        }
    }

    /// Wire-format user string: e.g., `user:01HK...`.
    pub fn user_wire(&self) -> String {
        format!("{}:{}", self.user_type, self.user_id)
    }

    /// Wire-format object string: e.g., `workspace:01HK...`.
    pub fn object_wire(&self) -> String {
        format!("{}:{}", self.object_type, self.object_id)
    }

    /// Idempotency key for the outbox poller. Format matches the convention in
    /// the auth ADR: `{op}-{object_type}-{object_id}-{relation}-{user_type}-{user_id}-{model_version}`.
    pub fn idempotency_key(&self, op: TupleOp, model_version: u32) -> String {
        format!(
            "{}-{}-{}-{}-{}-{}-v{}",
            op,
            self.object_type,
            self.object_id,
            self.relation,
            self.user_type,
            self.user_id,
            model_version,
        )
    }
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum TupleOp {
    Write,
    Delete,
}

impl fmt::Display for TupleOp {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str(match self {
            TupleOp::Write => "write",
            TupleOp::Delete => "delete",
        })
    }
}
```

`crates/moa-auth/authz-schema/src/schema_v1.fga` (the OpenFGA DSL — schema 1.2):

```
model
  schema 1.2

type user

type agent
  relations
    define tenant: [tenant]
    define operator: [user]
    define can_act_as: [user]

type api_key
  relations
    define tenant: [tenant]
    define owner: [user, agent]
    # `principal` lets authz checks substitute an api_key for its owner.
    define principal: owner

type tenant
  relations
    define admin: [user]
    define billing_admin: [user] or admin
    define member: [user] or admin

type workspace
  relations
    define tenant: [tenant]
    define admin: [user] or admin from tenant
    define editor: [user] or admin
    define member: [user] or editor or member from tenant

type session
  relations
    define workspace: [workspace]
    define owner: [user, agent]
    define participant: [user, agent] or owner or member from workspace

type knowledge_base
  relations
    define workspace: [workspace]
    define admin: [user] or admin from workspace
    define writer: [user, agent] or admin
    define reader: [user, agent] or writer or member from workspace

type document
  relations
    define knowledge_base: [knowledge_base]
    define owner: [user, agent]
    define reader: [user, agent] or owner or reader from knowledge_base
    define writer: [user, agent] or owner or writer from knowledge_base

type agent_template
  relations
    define tenant: [tenant]
    define creator: [user]
```

```rust
mod tests {
```

`crates/moa-auth/fga-bootstrap/src/main.rs`:

```rust
//! Idempotent OpenFGA bootstrap.
//!
//! On each run:
//!   1. Ensures a store named MOA_OPENFGA_STORE_NAME exists; creates if not.
//!   2. Writes the schema v1 model; the resulting model_id is appended to the
//!      store's model history (never overwriting prior versions).
//!   3. Runs three smoke checks against a known synthetic tuple.
//!   4. Writes `STORE_ID=...` / `MODEL_ID=...` to .env.fga at repo root and
//!      echoes them to stdout for shell sourcing.
//!
//! Designed to be safe to re-run. Calling this twice on a clean stack writes
//! the model twice (OpenFGA keeps both); the latest model_id is what
//! production reads.

use anyhow::{bail, Context, Result};
use clap::Parser;
use moa_authz_schema::{ObjectType, Relation, SCHEMA_V1_DSL, TupleKey, UserType};
use std::path::PathBuf;
use uuid::Uuid;

mod http;

#[derive(Parser, Debug)]
struct Args {
    /// OpenFGA HTTP base URL.
    #[arg(long, env = "MOA_OPENFGA_URL", default_value = "http://localhost:8081")]
    url: String,

    /// Preshared key.
    #[arg(long, env = "MOA_OPENFGA_PRESHARED_KEY")]
    preshared_key: String,

    /// Store name. Idempotent: existing store with this name is reused.
    #[arg(long, env = "MOA_OPENFGA_STORE_NAME", default_value = "moa")]
    store_name: String,

    /// Where to write the env file. Default: `.env.fga` at repo root.
    #[arg(long, env = "MOA_FGA_ENV_OUTPUT", default_value = ".env.fga")]
    env_output: PathBuf,

    /// Skip smoke checks. Use only for CI bootstrap, never locally.
    #[arg(long, env = "MOA_FGA_BOOTSTRAP_SKIP_SMOKE", default_value_t = false)]
    skip_smoke: bool,
}

#[tokio::main]
async fn main() -> Result<()> {
    tracing_subscriber::fmt()
        .with_env_filter(
            tracing_subscriber::EnvFilter::try_from_default_env()
                .unwrap_or_else(|_| tracing_subscriber::EnvFilter::new("info")),
        )
        .compact()
        .init();

    let args = Args::parse();
    let client = http::FgaClient::new(&args.url, &args.preshared_key)?;

    // ------ 1. ensure store ------
    let store_id = match client.find_store_by_name(&args.store_name).await? {
        Some(id) => {
            tracing::info!(store_id = %id, store_name = %args.store_name, "reusing existing store");
            id
        }
        None => {
            let id = client.create_store(&args.store_name).await?;
            tracing::info!(store_id = %id, store_name = %args.store_name, "created store");
            id
        }
    };

    // ------ 2. write model (always appends; latest wins) ------
    let model_id = client
        .write_authorization_model_from_dsl(&store_id, SCHEMA_V1_DSL)
        .await
        .context("write_authorization_model")?;
    tracing::info!(model_id = %model_id, "wrote schema v1 model");

    // ------ 3. smoke checks ------
    if !args.skip_smoke {
        run_smoke_checks(&client, &store_id, &model_id).await?;
    }

    // ------ 4. emit env ------
    let env_content = format!(
        "# generated by moa-fga-bootstrap; safe to re-source\n\
         MOA_OPENFGA_URL={}\n\
         MOA_OPENFGA_PRESHARED_KEY={}\n\
         MOA_OPENFGA_STORE_ID={}\n\
         MOA_OPENFGA_MODEL_ID={}\n",
        args.url, args.preshared_key, store_id, model_id,
    );
    std::fs::write(&args.env_output, &env_content)
        .with_context(|| format!("write {}", args.env_output.display()))?;
    println!("{}", env_content);

    Ok(())
}

async fn run_smoke_checks(
    client: &http::FgaClient,
    store_id: &str,
    model_id: &str,
) -> Result<()> {
    // Use deterministic synthetic IDs so this is replayable and visible in the
    // OpenFGA Playground.
    let tenant_id = Uuid::parse_str("00000000-0000-0000-0000-00000000ffff").unwrap();
    let workspace_id = Uuid::parse_str("00000000-0000-0000-0000-00000000fffe").unwrap();
    let user_id = Uuid::parse_str("00000000-0000-0000-0000-00000000fffd").unwrap();

    // Make user a tenant admin, workspace child of tenant, then verify the
    // inheritance chain works.
    let tenant_admin = TupleKey::new(
        UserType::User, user_id, Relation::Admin,
        ObjectType::Tenant, tenant_id,
    );
    let ws_parent = TupleKey::new(
        UserType::User /* ignored */, tenant_id, Relation::Tenant,
        ObjectType::Workspace, workspace_id,
    );
    // ws_parent is awkward: the "user" side is actually `tenant:<id>`, not
    // `user:<id>`. Our TupleKey newtype is uniform; the wire serializer in
    // `http.rs` special-cases this when user_type == User but the relation
    // targets a non-user. For the smoke, we'll write it via a dedicated
    // helper instead. See http::write_tuples_raw.

    client
        .write_tuples_raw(
            store_id,
            model_id,
            &[
                serde_json::json!({
                    "user": format!("user:{}", user_id),
                    "relation": "admin",
                    "object": format!("tenant:{}", tenant_id),
                }),
                serde_json::json!({
                    "user": format!("tenant:{}", tenant_id),
                    "relation": "tenant",
                    "object": format!("workspace:{}", workspace_id),
                }),
            ],
        )
        .await
        .context("write smoke tuples")?;

    // Check: tenant admin → workspace admin (via `admin from tenant`)
    let admin_check = client
        .check(
            store_id,
            model_id,
            &format!("user:{}", user_id),
            "admin",
            &format!("workspace:{}", workspace_id),
        )
        .await?;
    if !admin_check {
        bail!("smoke Check failed: user expected to be workspace admin via tenant inheritance");
    }
    tracing::info!("smoke Check ok: user→workspace admin via tenant");

    // ListObjects: list workspaces user has admin on
    let listed = client
        .list_objects(
            store_id, model_id, "workspace", "admin", &format!("user:{}", user_id),
        )
        .await?;
    let expected = format!("workspace:{}", workspace_id);
    if !listed.contains(&expected) {
        bail!(
            "smoke ListObjects failed: expected {} in {:?}",
            expected, listed
        );
    }
    tracing::info!("smoke ListObjects ok");

    // BatchCheck: confirm two checks land in one round-trip
    let batch = client
        .batch_check(
            store_id,
            model_id,
            &[
                (
                    format!("user:{}", user_id),
                    "admin".into(),
                    format!("workspace:{}", workspace_id),
                ),
                (
                    format!("user:{}", user_id),
                    "member".into(),
                    format!("workspace:{}", workspace_id),
                ),
            ],
        )
        .await?;
    if batch.len() != 2 || !batch.iter().all(|b| *b) {
        bail!("smoke BatchCheck failed: expected [true, true], got {:?}", batch);
    }
    tracing::info!("smoke BatchCheck ok");

    // Cleanup: delete the smoke tuples so the store is clean for tests.
    client
        .delete_tuples_raw(
            store_id,
            model_id,
            &[
                serde_json::json!({
                    "user": format!("user:{}", user_id),
                    "relation": "admin",
                    "object": format!("tenant:{}", tenant_id),
                }),
                serde_json::json!({
                    "user": format!("tenant:{}", tenant_id),
                    "relation": "tenant",
                    "object": format!("workspace:{}", workspace_id),
                }),
            ],
        )
        .await
        .context("cleanup smoke tuples")?;

    Ok(())
}
```

```rust
//! Minimal OpenFGA HTTP client for bootstrap.
//!
//! Intentionally not the production client (that lives in `moa-authz` in
//! P1.2). This implementation favors clarity and explicit error handling
//! over abstraction; it is dropped once the production client lands.

use anyhow::{bail, Context, Result};
use reqwest::Client;
use serde::Deserialize;
use serde_json::json;

pub struct FgaClient {
    base: String,
    http: Client,
    token: String,
}

impl FgaClient {
    pub fn new(base: &str, token: &str) -> Result<Self> {
        Ok(Self {
            base: base.trim_end_matches('/').to_string(),
            http: Client::builder().build()?,
            token: token.to_string(),
        })
    }

    pub async fn find_store_by_name(&self, name: &str) -> Result<Option<String>> {
        #[derive(Deserialize)]
        struct StoresResp { stores: Vec<Store> }
        #[derive(Deserialize)]
        struct Store { id: String, name: String }

        let mut url = format!("{}/stores", self.base);
        // Page through all stores (small N in practice).
        let mut continuation: Option<String> = None;
        loop {
            let r = self
                .http
                .get(&url)
                .bearer_auth(&self.token)
                .query(&[("continuation_token", continuation.as_deref().unwrap_or(""))])
                .send()
                .await?
                .error_for_status()?
                .json::<serde_json::Value>()
                .await?;
            let stores: StoresResp = serde_json::from_value(r.clone())?;
            for s in stores.stores {
                if s.name == name {
                    return Ok(Some(s.id));
                }
            }
            let next = r.get("continuation_token").and_then(|v| v.as_str()).unwrap_or("");
            if next.is_empty() {
                return Ok(None);
            }
            continuation = Some(next.to_string());
            url = format!("{}/stores", self.base);
        }
    }

    pub async fn create_store(&self, name: &str) -> Result<String> {
        let r = self
            .http
            .post(format!("{}/stores", self.base))
            .bearer_auth(&self.token)
            .json(&json!({ "name": name }))
            .send()
            .await?;
        if !r.status().is_success() {
            let status = r.status();
            let body = r.text().await.unwrap_or_default();
            bail!("CreateStore failed {}: {}", status, body);
        }
        let v: serde_json::Value = r.json().await?;
        v.get("id")
            .and_then(|s| s.as_str())
            .map(|s| s.to_string())
            .context("CreateStore response missing id")
    }

    /// Transform DSL to JSON via the `fga` CLI, then call
    /// `WriteAuthorizationModel`. Returns the new authorization_model_id.
    ///
    /// NOTE: OpenFGA's HTTP API does not accept DSL directly; it expects the
    /// JSON form. The `fga` CLI is the only supported transform. P1.2's
    /// production client will use the same approach but lazy-load the CLI.
    pub async fn write_authorization_model_from_dsl(
        &self,
        store_id: &str,
        dsl: &str,
    ) -> Result<String> {
        let json_model = transform_dsl_to_json(dsl)?;
        let r = self
            .http
            .post(format!("{}/stores/{}/authorization-models", self.base, store_id))
            .bearer_auth(&self.token)
            .json(&json_model)
            .send()
            .await?;
        if !r.status().is_success() {
            let status = r.status();
            let body = r.text().await.unwrap_or_default();
            bail!("WriteAuthorizationModel failed {}: {}", status, body);
        }
        let v: serde_json::Value = r.json().await?;
        v.get("authorization_model_id")
            .and_then(|s| s.as_str())
            .map(|s| s.to_string())
            .context("WriteAuthorizationModel response missing authorization_model_id")
    }

    pub async fn write_tuples_raw(
        &self,
        store_id: &str,
        model_id: &str,
        tuples: &[serde_json::Value],
    ) -> Result<()> {
        let r = self
            .http
            .post(format!("{}/stores/{}/write", self.base, store_id))
            .bearer_auth(&self.token)
            .json(&json!({
                "authorization_model_id": model_id,
                "writes": { "tuple_keys": tuples },
            }))
            .send()
            .await?;
        if !r.status().is_success() {
            let status = r.status();
            let body = r.text().await.unwrap_or_default();
            bail!("Write failed {}: {}", status, body);
        }
        Ok(())
    }

    pub async fn delete_tuples_raw(
        &self,
        store_id: &str,
        model_id: &str,
        tuples: &[serde_json::Value],
    ) -> Result<()> {
        let r = self
            .http
            .post(format!("{}/stores/{}/write", self.base, store_id))
            .bearer_auth(&self.token)
            .json(&json!({
                "authorization_model_id": model_id,
                "deletes": { "tuple_keys": tuples },
            }))
            .send()
            .await?;
        if !r.status().is_success() {
            let status = r.status();
            let body = r.text().await.unwrap_or_default();
            bail!("Delete failed {}: {}", status, body);
        }
        Ok(())
    }

    pub async fn check(
        &self,
        store_id: &str,
        model_id: &str,
        user: &str,
        relation: &str,
        object: &str,
    ) -> Result<bool> {
        let r = self
            .http
            .post(format!("{}/stores/{}/check", self.base, store_id))
            .bearer_auth(&self.token)
            .json(&json!({
                "authorization_model_id": model_id,
                "tuple_key": { "user": user, "relation": relation, "object": object },
            }))
            .send()
            .await?
            .error_for_status()?;
        let v: serde_json::Value = r.json().await?;
        Ok(v.get("allowed").and_then(|b| b.as_bool()).unwrap_or(false))
    }

    pub async fn list_objects(
        &self,
        store_id: &str,
        model_id: &str,
        object_type: &str,
        relation: &str,
        user: &str,
    ) -> Result<Vec<String>> {
        let r = self
            .http
            .post(format!("{}/stores/{}/list-objects", self.base, store_id))
            .bearer_auth(&self.token)
            .json(&json!({
                "authorization_model_id": model_id,
                "type": object_type,
                "relation": relation,
                "user": user,
            }))
            .send()
            .await?
            .error_for_status()?;
        let v: serde_json::Value = r.json().await?;
        Ok(v.get("objects")
            .and_then(|a| a.as_array())
            .map(|a| a.iter().filter_map(|x| x.as_str().map(String::from)).collect())
            .unwrap_or_default())
    }

    pub async fn batch_check(
        &self,
        store_id: &str,
        model_id: &str,
        items: &[(String, String, String)],
    ) -> Result<Vec<bool>> {
        let checks: Vec<serde_json::Value> = items
            .iter()
            .enumerate()
            .map(|(i, (u, r, o))| {
                json!({
                    "tuple_key": { "user": u, "relation": r, "object": o },
                    "correlation_id": format!("c{}", i),
                })
            })
            .collect();

        let r = self
            .http
            .post(format!("{}/stores/{}/batch-check", self.base, store_id))
            .bearer_auth(&self.token)
            .json(&json!({
                "authorization_model_id": model_id,
                "checks": checks,
            }))
            .send()
            .await?
            .error_for_status()?;
        let v: serde_json::Value = r.json().await?;

        // OpenFGA v1.8.x returns a `result` map keyed by correlation_id.
        // Earlier docs called this `results`; tolerate both via serde's
        // best-effort lookup.
        let map = v
            .get("result")
            .or_else(|| v.get("results"))
            .and_then(|x| x.as_object())
            .context("BatchCheck response missing result")?;
        let mut out = Vec::with_capacity(items.len());
        for (i, _) in items.iter().enumerate() {
            let key = format!("c{}", i);
            let entry = map.get(&key).context("BatchCheck missing correlation entry")?;
            out.push(entry.get("allowed").and_then(|b| b.as_bool()).unwrap_or(false));
        }
        Ok(out)
    }
}

/// Shell out to the `fga` CLI to convert DSL to JSON. The CLI is installed
/// via `make fga-install` and is on the developer's PATH. CI installs it
/// in a setup step.
fn transform_dsl_to_json(dsl: &str) -> Result<serde_json::Value> {
    use std::io::Write;
    use std::process::{Command, Stdio};

    // Write DSL to a tempfile because the `fga model transform` CLI in v0.6+
    // expects a path. (The `--dsl` flag was removed.)
    let mut tmp = tempfile::Builder::new()
        .prefix("moa-fga-model-")
        .suffix(".fga")
        .tempfile()?;
    tmp.write_all(dsl.as_bytes())?;
    let path = tmp.path().to_owned();

    let out = Command::new("fga")
        .args(["model", "transform", "--file", path.to_str().unwrap()])
        .stdout(Stdio::piped())
        .stderr(Stdio::piped())
        .output()
        .context("invoke fga CLI; run `make fga-install` if missing")?;
    if !out.status.success() {
        bail!(
            "fga model transform failed: {}",
            String::from_utf8_lossy(&out.stderr)
        );
    }
    let json: serde_json::Value = serde_json::from_slice(&out.stdout)
        .context("parse fga model transform output")?;
    Ok(json)
}
```

```rust
    let first_store_id = grep_env(&first_stdout, "MOA_OPENFGA_STORE_ID");

    // Second run: must reuse the same store_id.
    let second = Command::new(bin)
        .env("MOA_OPENFGA_STORE_NAME", "moa-test-idempotent")

    );

        .lines()
```

## Notes

- **Why a separate logical Postgres database for OpenFGA**, not a schema in
  the main `moa` database: OpenFGA's migration tool issues DDL freely and
  expects to own the database. Mixing it with MOA's schema invites version-
  drift bugs and complicates backups. The per-database cost on a single
  Postgres cluster is negligible.
- **Why include the DSL in the binary**, not load it from a file at runtime:
  the schema is part of the security contract. Loading it from disk at
  runtime would let a misconfigured deployment apply a different model than
  what was reviewed at commit time. `include_str!` makes the bytes part of
  the binary.
- **Why a model write appends rather than replaces**: OpenFGA model writes
  always create a new model_id; old tuples written against an earlier
  model_id remain valid until rewritten. This is the migration path —
  schema v2 can deploy alongside v1 and gradually re-tuple objects.
- **The smoke checks are not optional**. A bootstrap that "succeeds" but
  produces a model that does not enforce `admin from tenant` is the worst
  failure mode. The smoke tests catch that.
- **`fga` CLI dependency**: the CLI is required because OpenFGA's HTTP API
  does not accept DSL directly. Production builds of MOA do not need the
  CLI — only `moa-fga-bootstrap` does. CI should install it in a setup
  step; deployment images need not.
- **OpenFGA v1.8.16 API note**: BatchCheck returns `result` (singular) keyed
  by `correlation_id`. Earlier docs referenced `results`. The client tries
  both for forward/backward compatibility.
- **`#[ignore]` rationale**: live tests against a real OpenFGA cannot run in
  default `cargo test`; CI runs them explicitly via
  `cargo test -- --ignored` with the env flag set. This follows the
  existing pattern in `moa-orchestrator/tests/`.
- **Cleanup**: smoke tuples are deleted at the end of the smoke run so the
  store is in a clean state for P1.2 outbox tests. If smoke fails partway,
  tuples may remain — re-run is safe (idempotent), and the Playground
  shows the bad state for debugging.
