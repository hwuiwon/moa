# P1.6 — Local Auth Provider Stack (Zero-Deps Defaults)

## Purpose

Complete the local-only provider stack so `make dev` produces a system that
works end-to-end with **no external SaaS dependencies** — no Auth0, no third-
party token vault, no out-of-band approval service. After this prompt, a
self-hosted single-tenant deployment is fully functional with the defaults.

End state:

- `moa-auth-providers` ships three trait implementations:
  - `LocalAuthProvider` (already in P1.5) — API keys only.
  - `NullTokenVaultProvider` (new) — returns `TokenVaultError::NotConfigured`
    for every call. Lets handlers compile against `dyn TokenVaultProvider`
    without forcing a real vault.
  - `BuiltinAsyncAuthzProvider` (new) — in-app human-in-the-loop approval
    workflow backed by a Postgres table and Restate awakeables.
- A `Providers` bundle struct centralizes the three trait objects so callers
  don't accumulate ad-hoc `Arc<dyn ...>` fields.
- A `build_providers()` factory reads `[auth]`, `[token_vault]`,
  `[async_authz]` config sections and constructs the right `Providers`
  bundle. The default (no env vars set) is `local + none + builtin`.
- Orchestrator exposes `/v1/approvals` (list pending) and
  `POST /v1/approvals/:id/decision` (resolve). Resolving an approval
  completes the Restate awakeable that triggered it.
- `moa-cli approvals list | approve <id> | deny <id> [--reason ...]` works.
- `moa-cli auth use-key <key>` stores an API key in
  `~/.moa/credentials.json` so the CLI does not need the
  `bootstrap-cli-identity.sh` workaround from P1.5 for daily use.
- The Phase 1 milestone gate is met: a developer can hit `moa-edge` with an
  API key, create a session, and have a handler pause on a builtin
  approval that the user resolves via `moa-cli approvals approve`.

## Prerequisites

- P1.5 merged. `moa-auth-providers::LocalAuthProvider` is wired into
  `moa-edge`. API keys flow end-to-end.
- The orchestrator has at least one handler that can demonstrate an
  approval pause (a stub `tool_dispatch` handler is acceptable for the
  test surface; a real one is better).

### 2. Migration for builtin approvals

`crates/moa-auth-providers/migrations/20260514000000_builtin_approvals.up.sql`:

```sql
-- Pending approval requests for the BuiltinAsyncAuthzProvider.
--
-- A handler calls `request_approval` which writes a row here and returns a
-- handle containing the Restate awakeable id. When a user POSTs to
-- /v1/approvals/:id/decision, the orchestrator handler updates this row
-- AND resolves the awakeable with the decision payload. The waiting
-- workflow unblocks.
--
-- The row is the durable record of the approval; the awakeable is the
-- one-shot resolution mechanism. Both must be present for correctness:
-- awakeable alone is opaque; row alone is not actionable.

CREATE TABLE builtin_pending_approvals (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id      UUID        NOT NULL,
    -- The user whose decision we're waiting on (may differ from session.user_id
    -- when an agent is acting on behalf of someone else).
    deciding_user_id UUID       NOT NULL,
    tenant_id       UUID        NOT NULL,
    awakeable_id    TEXT        NOT NULL UNIQUE,
    action_summary  TEXT        NOT NULL,
    action_details  JSONB       NOT NULL,
    status          TEXT        NOT NULL DEFAULT 'pending'
                                CHECK (status IN ('pending', 'approved', 'denied', 'timeout')),
    deny_reason     TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at      TIMESTAMPTZ NOT NULL,
    decided_at      TIMESTAMPTZ,
    decided_by_user_id UUID
);

CREATE INDEX idx_builtin_approvals_pending
    ON builtin_pending_approvals(deciding_user_id, created_at DESC)
    WHERE status = 'pending';

CREATE INDEX idx_builtin_approvals_session
    ON builtin_pending_approvals(session_id);

-- Sweep index for timeout reaper.
CREATE INDEX idx_builtin_approvals_expires
    ON builtin_pending_approvals(expires_at)
    WHERE status = 'pending';
```

`.down.sql` drops the table.

### 4. `BuiltinAsyncAuthzProvider`

`crates/moa-auth-providers/src/builtin_authz.rs`:

```rust
//! Builtin async authorization: row in Postgres + Restate awakeable.
//!
//! The provider stores the request; the orchestrator's approvals service
//! (Step 6 below) resolves the awakeable when the user decides. Decoupling
//! the storage from the resolution mechanism lets us swap in other
//! providers (Auth0 CIBA in P1.8) without changing the handlers.

use async_trait::async_trait;
use chrono::{DateTime, Duration as ChronoDuration, Utc};
use moa_core::traits::{
    ApprovalDecision, ApprovalHandle, ApprovalRequest, AsyncAuthzError, AsyncAuthzProvider,
};
use serde_json::json;
use sqlx::PgPool;
use std::sync::Arc;
use uuid::Uuid;

pub struct BuiltinAsyncAuthzProvider {
    pool: Arc<PgPool>,
}

impl BuiltinAsyncAuthzProvider {
    pub fn new(pool: Arc<PgPool>) -> Self { Self { pool } }
}

#[async_trait]
impl AsyncAuthzProvider for BuiltinAsyncAuthzProvider {
    async fn request_approval(
        &self,
        request: ApprovalRequest,
    ) -> Result<ApprovalHandle, AsyncAuthzError> {
        let id = Uuid::new_v4();
        let timeout = ChronoDuration::from_std(request.timeout)
            .map_err(|e| AsyncAuthzError::Internal(format!("timeout: {e}")))?;
        let expires_at = Utc::now() + timeout;

        // We need tenant_id for the row but ApprovalRequest doesn't carry it.
        // The orchestrator caller wraps `request_approval` with a small
        // helper that derives tenant_id from the deciding user. For P1.6 we
        // require the caller to embed it in `action_details` under
        // `_tenant_id` (a leading underscore marks internal-only fields).
        let tenant_id: Uuid = request.action_details
            .get("_tenant_id")
            .and_then(|v| v.as_str())
            .and_then(|s| Uuid::parse_str(s).ok())
            .ok_or_else(|| AsyncAuthzError::Internal(
                "request.action_details._tenant_id required".into()
            ))?;

        sqlx::query(
            r#"
            INSERT INTO builtin_pending_approvals
                (id, session_id, deciding_user_id, tenant_id, awakeable_id,
                 action_summary, action_details, expires_at)
            VALUES ($1, $2, $3, $4, $5, $6, $7, $8)
            "#,
        )
        .bind(id)
        .bind(request.session_id)
        .bind(request.deciding_user_id)
        .bind(tenant_id)
        .bind(&request.awakeable_id)
        .bind(&request.action_summary)
        .bind(&request.action_details)
        .bind(expires_at)
        .execute(&*self.pool)
        .await
        .map_err(|e| AsyncAuthzError::Internal(format!("db: {e}")))?;

        Ok(ApprovalHandle {
            id,
            awakeable_id: request.awakeable_id,
            provider_specific: json!({ "kind": "builtin" }),
        })
    }

    /// Builtin does not poll — the orchestrator's POST handler resolves
    /// the awakeable directly when the user decides. We expose poll for
    /// completeness but it always returns None.
    async fn poll_decision(
        &self,
        _handle: &ApprovalHandle,
    ) -> Result<Option<ApprovalDecision>, AsyncAuthzError> {
        Ok(None)
    }

    fn name(&self) -> &'static str { "builtin" }
}

/// Row shape used by the approvals service handlers (see orchestrator).
#[derive(Debug, sqlx::FromRow)]
pub struct BuiltinApprovalRow {
    pub id: Uuid,
    pub session_id: Uuid,
    pub deciding_user_id: Uuid,
    pub tenant_id: Uuid,
    pub awakeable_id: String,
    pub action_summary: String,
    pub action_details: serde_json::Value,
    pub status: String,
    pub deny_reason: Option<String>,
    pub created_at: DateTime<Utc>,
    pub expires_at: DateTime<Utc>,
    pub decided_at: Option<DateTime<Utc>>,
    pub decided_by_user_id: Option<Uuid>,
}
```

### 5. `Providers` bundle + factory

`crates/moa-auth-providers/src/bundle.rs`:

```rust
use moa_core::config::{AsyncAuthzKind, AuthProviderKind, Config, TokenVaultKind};
use moa_core::traits::{AsyncAuthzProvider, AuthProvider, TokenVaultProvider};
use std::sync::Arc;
use thiserror::Error;

/// All three providers bundled together. Construct once at startup; clone
/// the bundle freely (each field is an Arc).
#[derive(Clone)]
pub struct Providers {
    pub auth: Arc<dyn AuthProvider>,
    pub token_vault: Arc<dyn TokenVaultProvider>,
    pub async_authz: Arc<dyn AsyncAuthzProvider>,
}

#[derive(Debug, Error)]
pub enum BuildError {
    #[error("auth provider '{0:?}' selected but feature not enabled")]
    AuthFeatureMissing(AuthProviderKind),
    #[error("token vault '{0:?}' selected but feature not enabled")]
    VaultFeatureMissing(TokenVaultKind),
    #[error("async authz '{0:?}' selected but feature not enabled")]
    AsyncAuthzFeatureMissing(AsyncAuthzKind),
    #[error("missing required config section: {0}")]
    MissingConfig(&'static str),
}

/// Read config; construct the right Providers bundle.
///
/// The Local + Null + Builtin path is unconditional — these implementations
/// live in this crate and need no Cargo features. Auth0 implementations
/// live in `moa-auth-providers-auth0` and are pulled in by P1.7 behind the
/// `auth0` feature; this function delegates to them via a `cfg(feature)`
/// dispatch.
pub fn build_providers(
    cfg: &Config,
    pool: Arc<sqlx::PgPool>,
) -> Result<Providers, BuildError> {
    let auth: Arc<dyn AuthProvider> = match cfg.auth.provider {
        AuthProviderKind::Local => Arc::new(crate::LocalAuthProvider::new(pool.clone())),
        AuthProviderKind::Auth0 => {
            #[cfg(feature = "auth0")]
            { return Err(BuildError::AuthFeatureMissing(AuthProviderKind::Auth0)); }
            #[cfg(not(feature = "auth0"))]
            { return Err(BuildError::AuthFeatureMissing(AuthProviderKind::Auth0)); }
        }
        AuthProviderKind::Oidc => {
            return Err(BuildError::AuthFeatureMissing(AuthProviderKind::Oidc));
        }
    };

    let token_vault: Arc<dyn TokenVaultProvider> = match cfg.token_vault.provider {
        TokenVaultKind::None => Arc::new(crate::NullTokenVaultProvider),
        TokenVaultKind::Auth0 => {
            return Err(BuildError::VaultFeatureMissing(TokenVaultKind::Auth0));
        }
    };

    let async_authz: Arc<dyn AsyncAuthzProvider> = match cfg.async_authz.provider {
        AsyncAuthzKind::Builtin => Arc::new(crate::BuiltinAsyncAuthzProvider::new(pool.clone())),
        AsyncAuthzKind::Auth0 => {
            return Err(BuildError::AsyncAuthzFeatureMissing(AsyncAuthzKind::Auth0));
        }
    };

    tracing::info!(
        auth = auth.name(),
        vault = token_vault.name(),
        async_authz = async_authz.name(),
        "providers bundle constructed"
    );
    Ok(Providers { auth, token_vault, async_authz })
}
```

### 6. Orchestrator approvals service

`crates/moa-orchestrator/src/services/approvals.rs`:

```rust
use moa_auth_providers::builtin_authz::BuiltinApprovalRow;
use moa_core::traits::ApprovalDecision;
use restate_sdk::prelude::*;
use serde::{Deserialize, Serialize};
use uuid::Uuid;

#[derive(Debug, Serialize, Deserialize)]
pub struct ApprovalSummary {
    pub id: Uuid,
    pub session_id: Uuid,
    pub action_summary: String,
    pub action_details: serde_json::Value,
    pub created_at: chrono::DateTime<chrono::Utc>,
    pub expires_at: chrono::DateTime<chrono::Utc>,
}

#[derive(Debug, Serialize, Deserialize)]
pub struct DecisionRequest {
    /// "approved" | "denied"
    pub outcome: String,
    pub reason: Option<String>,
}

#[restate_sdk::service]
pub trait Approvals {
    /// List approvals pending for the caller. Caller's identity must be a
    /// user (agents cannot resolve approvals on their own behalf).
    async fn list_mine(ctx: Context<'_>) -> Result<Vec<ApprovalSummary>, HandlerError>;

    /// Resolve an approval. Caller must be the deciding_user_id on the row
    /// (the user who was originally asked).
    async fn decide(ctx: Context<'_>, id: Uuid, req: DecisionRequest) -> Result<(), HandlerError>;
}

pub struct ApprovalsImpl;

impl Approvals for ApprovalsImpl {
    async fn list_mine(ctx: Context<'_>) -> Result<Vec<ApprovalSummary>, HandlerError> {
        let identity = crate::ctx::current_identity(&ctx)
            .map_err(|e| HandlerError::with_status(400, format!("bad identity: {e}")))?
            .ok_or_else(|| HandlerError::with_status(401, "identity required"))?;

        if identity.identity_type != moa_core::traits::IdentityType::User {
            return Err(HandlerError::with_status(403, "only users can list approvals"));
        }

        let pool = crate::pg_pool();
        let rows: Vec<BuiltinApprovalRow> = sqlx::query_as::<_, BuiltinApprovalRow>(
            r#"
            SELECT id, session_id, deciding_user_id, tenant_id, awakeable_id,
                   action_summary, action_details, status, deny_reason,
                   created_at, expires_at, decided_at, decided_by_user_id
            FROM builtin_pending_approvals
            WHERE deciding_user_id = $1 AND status = 'pending' AND expires_at > NOW()
            ORDER BY created_at DESC
            LIMIT 100
            "#,
        )
        .bind(identity.id)
        .fetch_all(pool)
        .await
        .map_err(|e| HandlerError::with_status(500, format!("db: {e}")))?;

        Ok(rows.into_iter().map(|r| ApprovalSummary {
            id: r.id,
            session_id: r.session_id,
            action_summary: r.action_summary,
            action_details: r.action_details,
            created_at: r.created_at,
            expires_at: r.expires_at,
        }).collect())
    }

    async fn decide(ctx: Context<'_>, id: Uuid, req: DecisionRequest) -> Result<(), HandlerError> {
        let identity = crate::ctx::current_identity(&ctx)
            .map_err(|e| HandlerError::with_status(400, format!("bad identity: {e}")))?
            .ok_or_else(|| HandlerError::with_status(401, "identity required"))?;

        if identity.identity_type != moa_core::traits::IdentityType::User {
            return Err(HandlerError::with_status(403, "only users can resolve approvals"));
        }

        let pool = crate::pg_pool();
        let mut tx = pool.begin().await
            .map_err(|e| HandlerError::with_status(500, format!("db: {e}")))?;

        // Lock the row; verify ownership; transition status; capture awakeable_id.
        let row: Option<BuiltinApprovalRow> = sqlx::query_as::<_, BuiltinApprovalRow>(
            r#"
            SELECT id, session_id, deciding_user_id, tenant_id, awakeable_id,
                   action_summary, action_details, status, deny_reason,
                   created_at, expires_at, decided_at, decided_by_user_id
            FROM builtin_pending_approvals
            WHERE id = $1
            FOR UPDATE
            "#,
        )
        .bind(id)
        .fetch_optional(&mut *tx)
        .await
        .map_err(|e| HandlerError::with_status(500, format!("db: {e}")))?;

        let row = row.ok_or_else(|| HandlerError::with_status(404, "not found"))?;

        if row.deciding_user_id != identity.id {
            return Err(HandlerError::with_status(403, "not your approval"));
        }
        if row.status != "pending" {
            return Err(HandlerError::with_status(409, format!("already {}", row.status)));
        }
        if row.expires_at <= chrono::Utc::now() {
            return Err(HandlerError::with_status(410, "expired"));
        }

        let (new_status, decision_payload) = match req.outcome.as_str() {
            "approved" => ("approved", serde_json::json!({ "outcome": "approved" })),
            "denied" => ("denied", serde_json::json!({
                "outcome": "denied",
                "reason": req.reason
            })),
            other => return Err(HandlerError::with_status(400, format!("bad outcome: {other}"))),
        };

        sqlx::query(
            r#"
            UPDATE builtin_pending_approvals
            SET status = $2, deny_reason = $3, decided_at = NOW(), decided_by_user_id = $4
            WHERE id = $1
            "#,
        )
        .bind(id)
        .bind(new_status)
        .bind(req.reason.as_deref())
        .bind(identity.id)
        .execute(&mut *tx)
        .await
        .map_err(|e| HandlerError::with_status(500, format!("db: {e}")))?;

        tx.commit().await
            .map_err(|e| HandlerError::with_status(500, format!("db commit: {e}")))?;

        // Resolve the awakeable AFTER the tx commits. If this fails (e.g.,
        // the workflow has already timed out and unregistered), log but do
        // not roll back — the row is the source of truth, and the workflow
        // will reconcile via timeout.
        let resolver = ctx.awakeable_resolver();
        if let Err(e) = resolver.resolve(&row.awakeable_id, &decision_payload).await {
            tracing::warn!(
                awakeable_id = %row.awakeable_id,
                error = ?e,
                "awakeable resolve failed; workflow may have already exited"
            );
        }
        Ok(())
    }
}

### 7. Builtin timeout reaper

Pending approvals can outlive their `expires_at`. A small background task
in the orchestrator transitions stale rows to `status='timeout'` and
resolves their awakeables with the timeout payload.

`crates/moa-orchestrator/src/services/approvals_reaper.rs`:

```rust
use sqlx::PgPool;
use std::sync::Arc;
use std::time::Duration;
use tokio::time::interval;

pub struct ApprovalReaper {
    pool: Arc<PgPool>,
    sweep_interval: Duration,
}

impl ApprovalReaper {
    pub fn new(pool: Arc<PgPool>) -> Self {
        Self { pool, sweep_interval: Duration::from_secs(30) }
    }

    pub fn spawn(self, awakeable_resolver: Arc<dyn AwakeableResolver>) -> tokio::task::JoinHandle<()> {
        tokio::spawn(async move {
            let mut tick = interval(self.sweep_interval);
            loop {
                tick.tick().await;
                if let Err(e) = self.sweep(awakeable_resolver.as_ref()).await {
                    tracing::error!(error = %e, "approval reaper sweep failed");
                }
            }
        })
    }

    async fn sweep(&self, resolver: &dyn AwakeableResolver) -> anyhow::Result<()> {
        let expired: Vec<(uuid::Uuid, String)> = sqlx::query_as(
            r#"
            UPDATE builtin_pending_approvals
            SET status = 'timeout'
            WHERE status = 'pending' AND expires_at <= NOW()
            RETURNING id, awakeable_id
            "#,
        )
        .fetch_all(&*self.pool)
        .await?;

        for (id, awakeable_id) in expired {
            let payload = serde_json::json!({ "outcome": "timeout" });
            if let Err(e) = resolver.resolve(&awakeable_id, &payload).await {
                tracing::warn!(approval_id = %id, error = ?e, "timeout resolve failed");
            }
        }
        Ok(())
    }
}

#[async_trait::async_trait]
pub trait AwakeableResolver: Send + Sync {
    async fn resolve(&self, awakeable_id: &str, payload: &serde_json::Value) -> anyhow::Result<()>;
}
```

Spawn the reaper from `main.rs` after the providers bundle is built. The
`AwakeableResolver` trait abstracts the Restate SDK's awakeable resolution
API; the production impl in `main.rs` wraps the SDK call.

// after the existing pool + outbox poller setup:

```markdown
# Builtin approvals

The default `async_authz.provider = "builtin"` configuration uses an in-app
approval workflow. Pending requests are stored in
`builtin_pending_approvals` and shown to users via `moa-cli approvals list`.

## User-facing flow

When an agent attempts an action that requires human approval, the workflow
pauses on a Restate awakeable. The user receives the approval out-of-band
(typically: an entry in `moa-cli approvals list` or a Slack/email push from
a future P1.10 hook). The user calls:

```sh
moa-cli approvals list
moa-cli approvals approve <id>   # or deny <id> --reason "wrong tool"
```

The workflow resumes within seconds.

## Operational notes

- Pending approvals time out after `async_authz.default_timeout_secs`
  (default 900s = 15 min). The reaper task sweeps every 30s.
- Resolved rows are kept indefinitely for audit. P1.10's OCSF pipeline
  emits an event for each decision.
- If the orchestrator restarts mid-decide, the row is already updated in
  Postgres but the awakeable may not have resolved. The next reaper sweep
  catches this and resolves with the recorded decision. (Implement this
  reconciliation in the reaper's sweep: also re-resolve rows in
  `status IN ('approved','denied')` whose `decided_at < NOW() - 1 min`
  and whose awakeable hasn't been confirmed-resolved. Bookkeeping for
  this is in P1.10 territory; P1.6 ships the optimistic path.)
```

## Notes

- **Why "Null" vault returns empty list_connections instead of an error**:
  the list endpoint is informational; an empty list is the correct answer
  ("you have no connections linked"). Callers iterating over it should not
  have to special-case the Null case.
- **Why `_tenant_id` is embedded in action_details**: the trait surface
  doesn't carry `tenant_id` on `ApprovalRequest`, but the row needs it for
  per-tenant access control and audit. Embedding it under a leading-
  underscore field is a temporary smell; P1.7 may add `tenant_id` to the
  trait if Auth0 needs it too. Document the convention in the trait
  comment.
- **Awakeable resolution is best-effort after row commit**: if Restate is
  unavailable when the user decides, the row is already updated and the
  workflow will eventually time out. The reaper can be extended to detect
  the "decided but unresolved" state and re-attempt resolution; ship the
  optimistic path in P1.6 and add the reconciliation in P1.10 along with
  proper observability.
- **`AwakeableResolver` trait** abstracts the Restate SDK API so the reaper
  can be tested with a mock resolver. The production resolver wraps
  `ctx.awakeable_resolver()`; the test resolver records resolutions in a
  Vec and asserts on them.
- **Why the edge constructs the full Providers bundle** when it only needs
  `auth`: P1.7 will swap in Auth0 by config alone — touching neither the
  edge nor the orchestrator code. Building the bundle uniformly is the
  forcing function for that property.
- **The reaper sweeps every 30 seconds, not every 1 second**: timeout
  granularity is human-scale; a 30s lag is invisible to users. Sweeping
  hot doesn't earn anything and adds DB load.
- **`auth use-key` stores the key in plaintext** at `~/.moa/credentials.json`
  with `0600` permissions. This matches what aws-cli, gh, and similar
  tools do. A hardened version would encrypt at rest with a passphrase or
  use the OS keychain; defer to a future prompt if customers ask.
- **The CLI talks to `moa-edge`**, not the orchestrator directly. This
  matters because `moa-edge` is where API key validation happens. Direct-
  to-orchestrator calls still work for testing (after re-binding port
  9080 to 127.0.0.1) but require manufactured identities.

## What P1.7 expects

- The Providers bundle factory exists; P1.7 swaps the `AuthProviderKind::Auth0`
  arm in `bundle.rs` from "feature missing" to a real constructor call
  (gated behind `cfg(feature = "auth0")`).
- `[auth.auth0]` config section is wired into `Config::auth.auth0`; P1.7's
  new crate just reads it.
- The `dyn AuthProvider` abstraction is the universal handler surface; no
  handler refers to `LocalAuthProvider` directly. Swapping in `Auth0AuthProvider`
  requires zero handler changes.
- The `moa-cli auth use-key` workflow is the local-mode parallel to
  P1.7's `moa-cli auth login`; both produce a `~/.moa/credentials.json`
  the rest of the CLI consumes uniformly.
