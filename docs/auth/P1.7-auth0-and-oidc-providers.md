# P1.7 — Auth0 + OIDC Provider Implementations

## Purpose

Add the first non-local identity provider implementations. After this
prompt, an operator can flip `MOA__AUTH__PROVIDER=auth0` (or `oidc`) and
get SSO without touching any handler code. Local API keys still work in
parallel — the bundle abstraction means swapping the auth provider does
not require disabling another.

End state:

- New crate `moa-auth-providers-auth0` behind a Cargo feature `auth0` (the
  feature flag prevents the heavy Auth0 SDK dependencies from being pulled
  into self-hosted deployments that don't need them).
- `Auth0AuthProvider` validates Auth0-issued RS256 JWTs against the
  configured tenant's JWKS, with key caching and rotation handling.
- Generic `OidcAuthProvider` does the same against any OIDC issuer
  (Okta, Microsoft Entra, Google Workspace, generic Keycloak).
- An optional background `OidcGroupSync` task polls the IdP for group
  membership changes and reconciles them as FGA tuples via the outbox.
- `build_providers()` in `moa-auth-providers` learns to construct these
  when the feature is enabled and the relevant config section is set.
- `hosted OIDC login` uses the OAuth 2.1 device-code flow to authenticate
  the hosted API under the configured Auth0/OIDC IdP and stores the resulting
  refresh token at `~/.moa/credentials.json` (replacing the API key for
  API users in Auth0 deployments).

## Prerequisites

- P1.6 merged. Providers bundle exists; the Auth0 arms in
  `build_providers` currently return `AuthFeatureMissing`.
- An Auth0 tenant (free dev tier is fine) and an API + Application
  registered, or a generic OIDC IdP. The reviewer/runner needs Auth0
  credentials to run the live tests.

## Read before starting

- `docs/architecture/decisions/0002-auth-architecture.md` decision 2 —
  Auth0 is opt-in; default stays local.
- `crates/moa-auth/providers/src/bundle.rs` — `build_providers` is the
  integration point.
- Auth0 quickstart for API JWT validation:
  <https://auth0.com/docs/quickstart/backend/rust>
- RFC 8414 (OAuth 2.0 Authorization Server Metadata) — `OidcAuthProvider`
  reads the issuer's `/.well-known/openid-configuration` to find JWKS URL,
  device authorization endpoint, etc.
- RFC 8628 (OAuth 2.0 Device Authorization Grant) — the `hosted API auth
  login` flow.

### 2. JWKS cache

`crates/moa-auth/auth0/src/jwks_cache.rs`:

```rust
//! In-memory JWKS cache. Refreshes on `kid` miss; expires entries after
//! `ttl` (default 1h). Thread-safe via tokio::sync::RwLock.

use jsonwebtoken::{jwk::JwkSet, DecodingKey};
use std::collections::HashMap;
use std::sync::Arc;
use std::time::{Duration, Instant};
use tokio::sync::RwLock;

#[derive(Clone)]
pub struct JwksCache {
    inner: Arc<RwLock<CacheState>>,
    jwks_url: String,
    http: reqwest::Client,
    ttl: Duration,
}

struct CacheState {
    keys: HashMap<String, DecodingKey>,
    fetched_at: Option<Instant>,
}

impl JwksCache {
    pub fn new(jwks_url: impl Into<String>, ttl: Duration) -> Self {
        Self {
            inner: Arc::new(RwLock::new(CacheState { keys: HashMap::new(), fetched_at: None })),
            jwks_url: jwks_url.into(),
            http: reqwest::Client::builder()
                .timeout(Duration::from_secs(10))
                .build().expect("reqwest client"),
            ttl,
        }
    }

    /// Get a decoding key by `kid`. Fetches+rebuilds the cache if the kid
    /// is missing or the cache is older than ttl.
    pub async fn key_for(&self, kid: &str) -> Result<DecodingKey, JwksError> {
        // Fast path: read lock, check kid + freshness.
        {
            let r = self.inner.read().await;
            if let Some(k) = r.keys.get(kid) {
                if r.fetched_at.map_or(false, |t| t.elapsed() < self.ttl) {
                    return Ok(k.clone());
                }
            }
        }
        // Slow path: refresh.
        self.refresh().await?;
        let r = self.inner.read().await;
        r.keys.get(kid)
            .cloned()
            .ok_or_else(|| JwksError::UnknownKid(kid.to_string()))
    }

    async fn refresh(&self) -> Result<(), JwksError> {
        tracing::info!(jwks_url = %self.jwks_url, "refreshing JWKS");
        let jwks: JwkSet = self.http
            .get(&self.jwks_url)
            .send().await
            .map_err(|e| JwksError::Http(e.to_string()))?
            .error_for_status()
            .map_err(|e| JwksError::Http(e.to_string()))?
            .json().await
            .map_err(|e| JwksError::Parse(e.to_string()))?;

        let mut keys = HashMap::new();
        for jwk in jwks.keys {
            let Some(kid) = jwk.common.key_id.clone() else { continue };
            match DecodingKey::from_jwk(&jwk) {
                Ok(k) => { keys.insert(kid, k); }
                Err(e) => tracing::warn!(?e, "skipping unsupported JWK"),
            }
        }
        let mut w = self.inner.write().await;
        w.keys = keys;
        w.fetched_at = Some(Instant::now());
        tracing::info!(count = w.keys.len(), "JWKS cache refreshed");
        Ok(())
    }
}

#[derive(Debug, thiserror::Error)]
pub enum JwksError {
    #[error("JWKS HTTP error: {0}")]
    Http(String),
    #[error("JWKS parse error: {0}")]
    Parse(String),
    #[error("unknown kid: {0}")]
    UnknownKid(String),
}
```

### 3. `Auth0AuthProvider`

`crates/moa-auth/auth0/src/auth0_provider.rs`:

```rust
use crate::jwks_cache::JwksCache;
use async_trait::async_trait;
use chrono::{DateTime, Utc};
use jsonwebtoken::{decode, decode_header, Algorithm, Validation};
use moa_core::traits::{AuthError, AuthProvider, Credential, Identity, IdentityType};
use serde::Deserialize;
use sqlx::PgPool;
use std::sync::Arc;
use std::time::Duration;
use uuid::Uuid;

pub struct Auth0AuthProvider {
    jwks: JwksCache,
    issuer: String,
    audience: String,
    /// We resolve sub -> user_id via a local mapping table (`auth0_user_map`).
    pool: Arc<PgPool>,
}

impl Auth0AuthProvider {
    pub fn new(domain: &str, audience: &str, pool: Arc<PgPool>) -> Self {
        let issuer = format!("https://{}/", domain.trim_end_matches('/'));
        let jwks_url = format!("{}.well-known/jwks.json", issuer);
        Self {
            jwks: JwksCache::new(jwks_url, Duration::from_secs(3600)),
            issuer,
            audience: audience.to_string(),
            pool,
        }
    }
}

#[derive(Debug, Deserialize)]
struct Auth0Claims {
    sub: String,                    // e.g., "auth0|abc123" or "google-oauth2|xyz"
    iss: String,
    aud: serde_json::Value,         // string or array
    exp: i64,
    // Auth0 namespaced claims; configure these via an Auth0 Action that
    // copies tenant_id and email into the access token. Without the Action
    // the claims won't be present and authenticate() returns Rejected.
    #[serde(rename = "https://moa/tenant_id")]
    tenant_id: Option<String>,
    #[serde(rename = "https://moa/identity_type", default)]
    identity_type: Option<String>,  // "user" | "agent" | "service"
}

#[async_trait]
impl AuthProvider for Auth0AuthProvider {
    async fn authenticate(&self, credential: &Credential) -> Result<Identity, AuthError> {
        let token = match credential {
            Credential::BearerJwt(t) => t,
            Credential::ApiKey(_) => return Err(AuthError::NotConfigured),
        };

        let header = decode_header(token)
            .map_err(|_| AuthError::InvalidFormat)?;
        let kid = header.kid.ok_or(AuthError::InvalidFormat)?;
        let key = self.jwks.key_for(&kid).await
            .map_err(|e| AuthError::Unavailable(format!("jwks: {e}")))?;

        let mut validation = Validation::new(Algorithm::RS256);
        validation.set_issuer(&[&self.issuer]);
        validation.set_audience(&[&self.audience]);
        validation.leeway = 30; // 30s clock skew tolerance.

        let data = decode::<Auth0Claims>(token, &key, &validation)
            .map_err(|e| match e.kind() {
                jsonwebtoken::errors::ErrorKind::ExpiredSignature => AuthError::Expired,
                _ => AuthError::Rejected,
            })?;
        let claims = data.claims;

        let tenant_str = claims.tenant_id.ok_or_else(|| AuthError::Internal(
            "auth0 token missing https://moa/tenant_id namespaced claim; configure the Auth0 Action".into()
        ))?;
        let tenant_id = Uuid::parse_str(&tenant_str)
            .map_err(|_| AuthError::Internal("tenant_id claim is not a UUID".into()))?;

        let id_type = match claims.identity_type.as_deref().unwrap_or("user") {
            "user" => IdentityType::User,
            "agent" => IdentityType::Agent,
            "service" => IdentityType::Service,
            other => return Err(AuthError::Internal(format!("unknown identity_type: {other}"))),
        };

        // Resolve auth0 sub -> internal user_id via the mapping table.
        // P1.9's SCIM provisioning populates this; for first login outside
        // SCIM, we just-in-time-provision a user row.
        let user_id = self.resolve_or_provision(&claims.sub, tenant_id, id_type).await
            .map_err(|e| AuthError::Internal(format!("resolve sub: {e}")))?;

        Ok(Identity {
            identity_type: id_type,
            id: user_id,
            tenant_id,
            api_key_id: None,
            acting_on_behalf_of: None,
        })
    }

    fn name(&self) -> &'static str { "auth0" }
}

impl Auth0AuthProvider {
    async fn resolve_or_provision(
        &self,
        sub: &str,
        tenant_id: Uuid,
        id_type: IdentityType,
    ) -> Result<Uuid, sqlx::Error> {
        // Atomic upsert: if (sub, tenant_id) exists, return its user_id;
        // otherwise insert with a new user_id and a `users` row.
        // The `auth0_user_map` table is created by a migration in this crate
        // (see Step 5).
        let mut tx = self.pool.begin().await?;
        let existing: Option<(Uuid,)> = sqlx::query_as(
            "SELECT user_id FROM auth0_user_map WHERE sub = $1 AND tenant_id = $2"
        )
        .bind(sub)
        .bind(tenant_id)
        .fetch_optional(&mut *tx)
        .await?;

        if let Some((uid,)) = existing {
            tx.commit().await?;
            return Ok(uid);
        }

        // JIT provision.
        let new_id = Uuid::new_v4();
        if id_type == IdentityType::User {
            sqlx::query(
                "INSERT INTO users (id, tenant_id, source, external_id, created_at)
                 VALUES ($1, $2, 'auth0', $3, NOW())
                 ON CONFLICT DO NOTHING"
            )
            .bind(new_id)
            .bind(tenant_id)
            .bind(sub)
            .execute(&mut *tx)
            .await?;
        }
        sqlx::query(
            "INSERT INTO auth0_user_map (sub, tenant_id, user_id) VALUES ($1, $2, $3)
             ON CONFLICT (sub, tenant_id) DO NOTHING"
        )
        .bind(sub)
        .bind(tenant_id)
        .bind(new_id)
        .execute(&mut *tx)
        .await?;
        tx.commit().await?;
        Ok(new_id)
    }
}
```

### 4. Generic `OidcAuthProvider`

`crates/moa-auth/auth0/src/oidc_provider.rs`:

```rust
//! Generic OIDC provider. Same shape as Auth0AuthProvider but reads
//! .well-known/openid-configuration at startup and allows the issuer +
//! audience + jwks_url to be configured directly.

use crate::jwks_cache::JwksCache;
use async_trait::async_trait;
use jsonwebtoken::{decode, decode_header, Algorithm, Validation};
use moa_core::traits::{AuthError, AuthProvider, Credential, Identity, IdentityType};
use serde::Deserialize;
use sqlx::PgPool;
use std::sync::Arc;
use std::time::Duration;
use uuid::Uuid;

pub struct OidcAuthProvider {
    jwks: JwksCache,
    issuer: String,
    audience: String,
    /// JSONPath-style claim names (overridable per-deployment).
    tenant_id_claim: String,
    identity_type_claim: String,
    pool: Arc<PgPool>,
}

impl OidcAuthProvider {
    pub fn new(
        issuer: String,
        audience: String,
        jwks_url: String,
        tenant_id_claim: Option<String>,
        identity_type_claim: Option<String>,
        pool: Arc<PgPool>,
    ) -> Self {
        Self {
            jwks: JwksCache::new(jwks_url, Duration::from_secs(3600)),
            issuer,
            audience,
            tenant_id_claim: tenant_id_claim.unwrap_or_else(|| "tenant_id".into()),
            identity_type_claim: identity_type_claim.unwrap_or_else(|| "identity_type".into()),
            pool,
        }
    }
}

#[derive(Debug, Deserialize)]
struct GenericClaims {
    sub: String,
    iss: String,
    exp: i64,
    #[serde(flatten)]
    extra: serde_json::Map<String, serde_json::Value>,
}

#[async_trait]
impl AuthProvider for OidcAuthProvider {
    async fn authenticate(&self, credential: &Credential) -> Result<Identity, AuthError> {
        let token = match credential {
            Credential::BearerJwt(t) => t,
            Credential::ApiKey(_) => return Err(AuthError::NotConfigured),
        };

        let header = decode_header(token).map_err(|_| AuthError::InvalidFormat)?;
        let kid = header.kid.ok_or(AuthError::InvalidFormat)?;
        let key = self.jwks.key_for(&kid).await
            .map_err(|e| AuthError::Unavailable(format!("jwks: {e}")))?;

        let mut v = Validation::new(Algorithm::RS256);
        v.set_issuer(&[&self.issuer]);
        v.set_audience(&[&self.audience]);
        v.leeway = 30;

        let data = decode::<GenericClaims>(token, &key, &v)
            .map_err(|e| match e.kind() {
                jsonwebtoken::errors::ErrorKind::ExpiredSignature => AuthError::Expired,
                _ => AuthError::Rejected,
            })?;
        let claims = data.claims;

        let tenant_str = claims.extra.get(&self.tenant_id_claim)
            .and_then(|v| v.as_str())
            .ok_or_else(|| AuthError::Internal(format!(
                "missing required claim: {}", self.tenant_id_claim
            )))?;
        let tenant_id = Uuid::parse_str(tenant_str)
            .map_err(|_| AuthError::Internal("tenant claim is not a UUID".into()))?;

        let id_type = match claims.extra.get(&self.identity_type_claim)
            .and_then(|v| v.as_str())
            .unwrap_or("user")
        {
            "user" => IdentityType::User,
            "agent" => IdentityType::Agent,
            "service" => IdentityType::Service,
            other => return Err(AuthError::Internal(format!("unknown identity_type: {other}"))),
        };

        // Same JIT provisioning pattern as Auth0 — share via a helper.
        let user_id = crate::auth0_provider::resolve_or_provision_static(
            &self.pool, &claims.sub, tenant_id, id_type, "oidc",
        )
        .await
        .map_err(|e| AuthError::Internal(format!("resolve sub: {e}")))?;

        Ok(Identity {
            identity_type: id_type,
            id: user_id,
            tenant_id,
            api_key_id: None,
            acting_on_behalf_of: None,
        })
    }

    fn name(&self) -> &'static str { "oidc" }
}
```

Refactor `resolve_or_provision` from `Auth0AuthProvider` into a free

in `auth0_provider.rs` so both providers share it. The `source` param

### 6. OIDC group → FGA tuple sync

`crates/moa-auth/auth0/src/group_sync.rs`:

```rust
//! Polls the IdP for user group memberships and reconciles them as FGA
//! tuples. Designed for Auth0's Management API but the trait `IdpGroupReader`
//! lets other IdPs plug in.
//!
//! Mapping convention: an IdP group named `tenant:<T>:workspace:<W>:admin`
//! maps to the FGA tuple `user:<U> admin workspace:<W>`. This is a flat
//! string convention chosen for simplicity; document the rule in
//! `docs/operations/oidc-group-mapping.md`.

use async_trait::async_trait;
use moa_authz::outbox::enqueue_raw;
use moa_authz_schema::{TupleOp, MODEL_VERSION};
use sqlx::PgPool;
use std::sync::Arc;
use std::time::Duration;
use tokio::time::interval;
use uuid::Uuid;

#[async_trait]
pub trait IdpGroupReader: Send + Sync {
    /// Return the list of group names this user belongs to.
    async fn groups_for(&self, sub: &str) -> Result<Vec<String>, anyhow::Error>;
}

pub struct OidcGroupSync {
    pool: Arc<PgPool>,
    reader: Arc<dyn IdpGroupReader>,
    sync_interval: Duration,
}

impl OidcGroupSync {
    pub fn new(pool: Arc<PgPool>, reader: Arc<dyn IdpGroupReader>) -> Self {
        Self { pool, reader, sync_interval: Duration::from_secs(60) }
    }

    pub fn spawn(self) -> tokio::task::JoinHandle<()> {
        tokio::spawn(async move {
            let mut tick = interval(self.sync_interval);
            loop {
                tick.tick().await;
                if let Err(e) = self.sync_once().await {
                    tracing::error!(error = %e, "group sync failed");
                }
            }
        })
    }

    async fn sync_once(&self) -> Result<(), anyhow::Error> {
        // Iterate all auth0/oidc users; for each, fetch groups; diff against
        // the desired tuple set; enqueue write/delete tuples via the outbox.
        // The desired tuples are recomputed from scratch each cycle —
        // simpler than maintaining an incremental view, and the outbox's
        // ON CONFLICT DO NOTHING makes repeated writes cheap.

        let users: Vec<(Uuid, Uuid, String)> = sqlx::query_as(
            "SELECT user_id, tenant_id, sub FROM auth0_user_map LIMIT 1000"
        )
        .fetch_all(&*self.pool)
        .await?;

        for (user_id, tenant_id, sub) in users {
            let groups = match self.reader.groups_for(&sub).await {
                Ok(g) => g,
                Err(e) => {
                    tracing::warn!(sub = %sub, error = %e, "groups_for failed; skipping");
                    continue;
                }
            };
            let desired = groups.iter().filter_map(|g| parse_group(g)).collect::<Vec<_>>();

            // For each desired tuple, enqueue a write. The outbox is idempotent.
            let mut tx = self.pool.begin().await?;
            for d in &desired {
                enqueue_raw(
                    &mut *tx,
                    TupleOp::Write,
                    &format!("user:{}", user_id),
                    &d.relation,
                    &format!("{}:{}", d.object_type, d.object_id),
                    Some(tenant_id),
                ).await?;
            }
            tx.commit().await?;

            // Note: this sync writes new tuples but does NOT delete tuples
            // for groups the user has been removed from. Tracking
            // last-synced-state per user to detect removals is real work;
            // P1.9 (SCIM) is the proper home for accurate revocation.
            // OIDC group sync is best-effort *additive* for P1.7.
        }
        Ok(())
    }
}

struct DesiredTuple {
    object_type: String,
    object_id: Uuid,
    relation: String,
}

fn parse_group(g: &str) -> Option<DesiredTuple> {
    // tenant:<T>:workspace:<W>:admin
    // tenant:<T>:workspace:<W>:member
    // tenant:<T>:admin
    let parts: Vec<&str> = g.split(':').collect();
    match parts.as_slice() {
        ["tenant", _t, "workspace", w, rel] => Some(DesiredTuple {
            object_type: "workspace".into(),
            object_id: Uuid::parse_str(w).ok()?,
            relation: (*rel).to_string(),
        }),
        ["tenant", t, rel] => Some(DesiredTuple {
            object_type: "tenant".into(),
            object_id: Uuid::parse_str(t).ok()?,
            relation: (*rel).to_string(),
        }),
        _ => None,
    }
}
```

The `Auth0GroupReader` impl uses Auth0's Management API; this is straight-
forward but credentialed. Ship a stub that errors with a clear message
when the management API client isn't configured. Self-hosted local Auth0
deployments without management API access just don't use group sync.

```rust
            let a0 = cfg.auth.auth0.as_ref()
                .ok_or(BuildError::MissingConfig("auth.auth0"))?;
            Arc::new(moa_auth_providers_auth0::Auth0AuthProvider::new(
                &a0.domain, &a0.audience, pool.clone(),
            ))
        }
        #[cfg(not(feature = "auth0"))] {
            return Err(BuildError::AuthFeatureMissing(AuthProviderKind::Auth0));
        }
    }
    AuthProviderKind::Oidc => {
        #[cfg(feature = "auth0")] {
            let o = cfg.auth.oidc.as_ref()
                .ok_or(BuildError::MissingConfig("auth.oidc"))?;
            Arc::new(moa_auth_providers_auth0::OidcAuthProvider::new(
                o.issuer.clone(), o.audience.clone(), o.jwks_url.clone(),
                None, None, pool.clone(),
            ))
        }
        #[cfg(not(feature = "auth0"))] {
            return Err(BuildError::AuthFeatureMissing(AuthProviderKind::Oidc));
        }
    }
};
```

Note: the `auth0` feature gates both Auth0 *and* generic OIDC; they share
the dependency on `jsonwebtoken`. If you want them separable, split into
`auth0` and `oidc` features later. For P1.7 keep them together.

### 9. `hosted OIDC login` (device-code flow)

Extend `crates/moa-orchestrator/src/services/api_keys.rs` with a `Login` variant that
performs OAuth 2.1 device authorization:

```rust
#[derive(Subcommand, Debug)]
pub enum AuthAction {
    Keys { /* ... */ },
    UseKey { key: String },
    /// Authenticate via the configured Auth0/OIDC tenant. Stores a refresh
    /// token at ~/.moa/credentials.json.
    Login {
        /// Override the IdP discovery URL (defaults to MOA_EDGE_URL/.well-known).
        #[arg(long)] issuer: Option<String>,
        #[arg(long)] client_id: Option<String>,
    },
}
```

Implementation outline (full body is straightforward but verbose; engineer
implements per RFC 8628):

1. Discover `device_authorization_endpoint`, `token_endpoint` from
   `<issuer>/.well-known/openid-configuration`.
2. POST `device_code` request with `client_id`, `scope=openid offline_access`.
3. Print `verification_uri_complete` (or `verification_uri` + `user_code`).
   Open the URL in the browser via `open` or `xdg-open` if available.
4. Poll `token_endpoint` with `grant_type=urn:ietf:params:oauth:grant-type:device_code`
   and `device_code` until non-pending.
5. On success, store both the access and refresh tokens in
   `~/.moa/credentials.json` with mode `0600`.
6. On subsequent API invocations, `client_from_credentials` reads the
   access token; if expired, refreshes via the refresh token; persists the
   new tokens.

The refresh flow lives in `moa-edge hosted API authentication` — extend the
existing `client_from_credentials` to detect token expiry and refresh
transparently. Hide the refresh logic behind a small `TokenStore` struct.

## Notes

- **Why feature-gate Auth0**: `jsonwebtoken` pulls in `ring` (RSA, ECDSA)
  which has a non-trivial compile-time cost. Self-hosted deployments that
  only need local API keys should not pay it. Feature-gating is the
  standard Rust idiom; CI matrix builds both configurations.
- **`https://moa/...` namespaced claims**: Auth0 requires custom claims
  in access tokens to be namespaced URIs. The `tenant_id` and
  `identity_type` claims are added by an Auth0 Action (post-login hook).
  Without the Action, validation succeeds but `tenant_id` is missing and
  authenticate returns `Internal(...)`. Document this prominently in the
  setup guide; it's the #1 failure mode for first-time Auth0 setup.
- **JIT provisioning vs SCIM**: P1.7's JIT path creates a `users` row on
  first login if not present. P1.9's SCIM path provisions proactively.
  When both are configured, SCIM wins (it runs before user login); JIT
  becomes a safety net for misconfigured SCIM pipelines.
- **Group sync is additive only in P1.7**: removing a user from a group
  in the IdP does NOT remove the corresponding FGA tuple. This is a known
  limitation; full reconciliation lands in P1.9 with the SCIM
  deactivation cascade. Document this clearly so operators don't expect
  removal semantics they don't get.
- **Why `Auth0AuthProvider` resolves sub→user_id via a table and not via
  the JWT alone**: agents and services have UUIDs that don't appear in
  the JWT. The table is the single source of truth for the (sub, tenant)
  → user_id mapping; the JWT only attests to the sub. This also makes
  user-rename (sub change in the IdP) recoverable: update the row, don't
  re-provision.
- **Token refresh in the hosted API**: store both access and refresh tokens.
  The refresh token has a long TTL (configurable in Auth0; default 30d).
  Pre-emptively refresh when the access token has <60s remaining; this
  avoids the user seeing an "expired" error mid-command.
- **`hosted OIDC login` works alongside API-key configuration**: the hosted API checks
  `credentials.json` for `api_key` first, then `access_token`. Operators
  in Auth0 deployments use `login`; everyone else uses `use-key`.
- **Why a single `auth0` feature gates both Auth0 and generic OIDC**: they
  share `jsonwebtoken` and `reqwest` and most of the validation logic.
  Splitting them earns nothing for the maintenance overhead. If a
  customer asks for OIDC without `ring`, revisit.
