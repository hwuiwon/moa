# P1.9 — SCIM v2 Endpoints and Deactivation Cascade

## Purpose

Make MOA a SCIM v2 endpoint so enterprise IdPs (Okta, Microsoft Entra,
Auth0 itself, Google Workspace) can provision users and groups
automatically. The hard part isn't the wire protocol — RFC 7644 is
straightforward — it's the deactivation cascade: when an IdP marks a
user inactive, MOA must atomically cancel their sessions, revoke their
API keys, remove their FGA tuples, and unlink their agents. Any single
stale state leaves a former employee with phantom access.

End state:

- SCIM v2 endpoints on the orchestrator:
  - `GET/POST/PUT/PATCH/DELETE /scim/v2/Users`
  - `GET/POST/PUT/PATCH/DELETE /scim/v2/Groups`
  - `GET /scim/v2/ServiceProviderConfig`
  - `GET /scim/v2/ResourceTypes`, `GET /scim/v2/Schemas`
- A dedicated `scim_admin` API key scope authenticates SCIM clients.
  No user-context auth on these endpoints; SCIM is machine-to-machine.
- Deactivation cascade runs in a single Postgres transaction:
  - `UPDATE users SET active=false, deactivated_at=NOW()`
  - For each active session: `cancel_session(...)` (existing handler)
  - For each non-revoked API key: `api_keys::revoke(...)` with reason `deactivation_cascade`
  - Enqueue outbox delete tuples for every FGA edge the user holds:
    `user:<id>` on tenant, workspace, knowledge_base, document, session
  - Enqueue outbox delete tuples for every `agent.operator user:<id>`
    edge (orphaned agents are left running but no longer have an
    operator; a follow-up sweeper retires them).
- Group membership maps to FGA tuples: SCIM Group → tenant/workspace
  relation per a configurable mapping (the same shape as P1.7's
  group sync).
- Idempotent: re-running the cascade for an already-deactivated user is
  a no-op (no errors, no extra outbox rows).
- Live integration tests `#[ignore]`-gated behind
  `MOA_RUN_LIVE_SCIM_TESTS=1`; Okta's SCIM Compliance Tester runs
  green against the dev stack.

This prompt does not add OCSF security events (P1.10) — though every
deactivation should emit one. The handlers TODO-mark those emit sites so
P1.10's wiring is a focused diff.

## Prerequisites

- P1.8 merged. Provider factory complete; agent identity lifecycle
  exists.
- A `users` table exists in Postgres with at least: `id UUID`,
  `tenant_id UUID`, `email TEXT`, `external_id TEXT`, `active BOOLEAN`,
  `deactivated_at TIMESTAMPTZ`, `created_at TIMESTAMPTZ`,
  `updated_at TIMESTAMPTZ`. If not, P1.9 includes the migration.

### 2. API key scope: `scim_admin`

P1.5 stores scopes as FGA tuples on `api_key:<id>`. SCIM admin scope is
modeled as a single tuple: `api_key:<id> scim_admin tenant:<T>`.

Extend the schema (a v2 model change). Add to
`crates/moa-auth/authz-schema/src/schema_v1.fga`:

```
type tenant
  relations
    define admin: [user]
    define billing_admin: [user] or admin
    define member: [user] or admin
    define scim_admin: [api_key]   # <-- new
```

Bump `MODEL_VERSION` in `crates/moa-auth/authz-schema/src/lib.rs` from `1` to
`2`. Run `moa-fga-bootstrap` to apply the new model; old tuples remain
valid under the old model_id.

Document in `docs/auth/scim.md`:

> SCIM clients authenticate with an API key whose scope grants
> `scim_admin` on the target tenant. Create one with:
>
> ```
> moa-cli auth keys create --name="okta-scim" --env=prod
> moa-cli authz tuple-write \
>   --user=api_key:<key_id> --relation=scim_admin --object=tenant:<tenant>
> ```
>
> Present as `Authorization: Bearer <key>` to all SCIM endpoints.

(`moa-cli authz tuple-write` is a small admin helper to add to the CLI;
it shells over a new `Authz::write_tuple` orchestrator endpoint that
checks the caller is `tenant.admin`. Implementation is mechanical;
sketch in Step 7.)

use super::auth::require_scim_admin;
use super::deactivation::cascade_deactivate_user;

// GET /scim/v2/Users
pub async fn list_users(
    State(state): State<ScimState>,
    Query(q): Query<ListQuery>,
    identity: ScimIdentity,
) -> Result<Json<ListResponse<ScimUser>>, ScimResponseError> {
    require_scim_admin(&identity.0, state.tenant_id).await
        .map_err(map_authz_error)?;

    let (start, count) = (q.start_index.unwrap_or(1).max(1), q.count.unwrap_or(50).min(200));

    // Filter parsing: SCIM clients commonly send
    //   filter=userName eq "alice@example.com"
    //   filter=externalId eq "okta-12345"
    // Support a minimal grammar: <attr> eq "<value>". Anything more
    // complex returns 400 with scim_type=invalidFilter.
    let filter = q.filter.as_deref().map(parse_filter).transpose()
        .map_err(|e| ScimResponseError::bad_request("invalidFilter", e))?;

    let rows = state.pool.acquire().await.map_err(map_db)?;
    let (total, page) = fetch_users_page(&state, &filter, start, count).await
        .map_err(map_db)?;

    Ok(Json(ListResponse {
        schemas: vec![SCHEMA_LIST.into()],
        total_results: total,
        items_per_page: page.len() as i64,
        start_index: start,
        resources: page,
    }))
}

// POST /scim/v2/Users
pub async fn create_user(
    State(state): State<ScimState>,
    identity: ScimIdentity,
    Json(req): Json<ScimUser>,
) -> Result<(StatusCode, Json<ScimUser>), ScimResponseError> {
    require_scim_admin(&identity.0, state.tenant_id).await
        .map_err(map_authz_error)?;

    let primary_email = req.emails.iter()
        .find(|e| e.primary == Some(true))
        .or(req.emails.first())
        .map(|e| e.value.as_str())
        .unwrap_or(&req.user_name);

    let mut tx = state.pool.begin().await.map_err(map_db)?;
    let user_id = Uuid::new_v4();
    let r = sqlx::query(
        r#"
        INSERT INTO users
            (id, tenant_id, email, external_id, given_name, family_name, display_name, active)
        VALUES ($1, $2, $3, $4, $5, $6, $7, $8)
        ON CONFLICT (tenant_id, email) DO NOTHING
        "#,
    )
    .bind(user_id)
    .bind(state.tenant_id)
    .bind(primary_email)
    .bind(req.external_id.as_deref())
    .bind(req.name.as_ref().and_then(|n| n.given_name.as_deref()))
    .bind(req.name.as_ref().and_then(|n| n.family_name.as_deref()))
    .bind(req.display_name.as_deref())
    .bind(req.active)
    .execute(&mut *tx)
    .await
    .map_err(map_db)?;

    if r.rows_affected() == 0 {
        return Err(ScimResponseError::conflict("uniqueness", "user with this email already exists"));
    }

    // Enqueue FGA tuple: user:<new> member tenant:<T>.
    moa_authz::outbox::enqueue_raw(
        &mut *tx,
        moa_authz_schema::TupleOp::Write,
        &format!("user:{user_id}"),
        "member",
        &format!("tenant:{}", state.tenant_id),
        Some(state.tenant_id),
    ).await.map_err(map_outbox)?;

    // TODO P1.10: emit OCSF iam.user.create here.

    tx.commit().await.map_err(map_db)?;

    let body = fetch_user_by_id(&state, user_id).await.map_err(map_db)?;
    Ok((StatusCode::CREATED, Json(body)))
}

// PATCH /scim/v2/Users/{id}
//
// Per RFC 7644 §3.5.2, PATCH is the operation enterprise IdPs use to
// flip `active` from true to false on deprovision. This is the cascade
// trigger.
pub async fn patch_user(
    State(state): State<ScimState>,
    Path(id): Path<Uuid>,
    identity: ScimIdentity,
    Json(op): Json<super::patch::PatchOp>,
) -> Result<Json<ScimUser>, ScimResponseError> {
    require_scim_admin(&identity.0, state.tenant_id).await
        .map_err(map_authz_error)?;

    let mutation = super::patch::interpret(&op)
        .map_err(|e| ScimResponseError::bad_request("invalidSyntax", e))?;

    let mut tx = state.pool.begin().await.map_err(map_db)?;

    // Apply attribute changes. We only support a small set in P1.9; SCIM
    // standard PATCH is mature but most enterprise IdPs send a tiny subset.
    if let Some(active) = mutation.active {
        if !active {
            // Deactivation: cascade.
            cascade_deactivate_user(&mut *tx, state.tenant_id, id).await
                .map_err(map_cascade)?;
        } else {
            // Re-activation: just flip the flag and re-enqueue the member tuple.
            sqlx::query("UPDATE users SET active=true, deactivated_at=NULL, updated_at=NOW(), version=version+1 WHERE id=$1")
                .bind(id).execute(&mut *tx).await.map_err(map_db)?;
            moa_authz::outbox::enqueue_raw(
                &mut *tx,
                moa_authz_schema::TupleOp::Write,
                &format!("user:{id}"),
                "member",
                &format!("tenant:{}", state.tenant_id),
                Some(state.tenant_id),
            ).await.map_err(map_outbox)?;
        }
    }
    // ... apply other attributes (email, name, etc.) ...

    tx.commit().await.map_err(map_db)?;
    let body = fetch_user_by_id(&state, id).await.map_err(map_db)?;
    Ok(Json(body))
}

// DELETE /scim/v2/Users/{id}
//
// Per RFC 7644, DELETE is "hard delete the resource." Enterprise IdPs
// rarely call this — they prefer PATCH active=false. But MOA must support
// it for SCIM compliance. We map it to the same cascade + a row delete
// at the end. GDPR hard-delete (Phase 4) is a different operation that
// scrubs PII; DELETE here removes the user row but leaves audit trails.
pub async fn delete_user(
    State(state): State<ScimState>,
    Path(id): Path<Uuid>,
    identity: ScimIdentity,
) -> Result<StatusCode, ScimResponseError> {
    require_scim_admin(&identity.0, state.tenant_id).await
        .map_err(map_authz_error)?;

    let mut tx = state.pool.begin().await.map_err(map_db)?;
    cascade_deactivate_user(&mut *tx, state.tenant_id, id).await.map_err(map_cascade)?;
    sqlx::query("DELETE FROM users WHERE id=$1").bind(id).execute(&mut *tx).await.map_err(map_db)?;
    // TODO P1.10: emit OCSF iam.user.delete here.
    tx.commit().await.map_err(map_db)?;
    Ok(StatusCode::NO_CONTENT)
}

`scim/patch.rs`:

```rust
//! Minimal RFC 7644 PATCH parser. Only supports the operations enterprise
//! IdPs actually send. Unknown ops return 400 with scim_type=invalidSyntax.

use serde::Deserialize;

#[derive(Debug, Deserialize)]
pub struct PatchOp {
    #[serde(rename = "Operations")]
    pub operations: Vec<Operation>,
    pub schemas: Vec<String>,
}

#[derive(Debug, Deserialize)]
pub struct Operation {
    pub op: String,            // "add" | "remove" | "replace"
    pub path: Option<String>,
    pub value: Option<serde_json::Value>,
}

#[derive(Debug, Default)]
pub struct Mutation {
    pub active: Option<bool>,
    pub email: Option<String>,
    pub display_name: Option<String>,
    pub given_name: Option<String>,
    pub family_name: Option<String>,
}

pub fn interpret(patch: &PatchOp) -> Result<Mutation, &'static str> {
    let mut m = Mutation::default();
    for op in &patch.operations {
        let path = op.path.as_deref().unwrap_or("");
        match (op.op.as_str(), path) {
            ("replace" | "add", "active") => {
                m.active = op.value.as_ref().and_then(|v| v.as_bool());
                if m.active.is_none() { return Err("active must be boolean"); }
            }
            ("replace" | "add", "displayName") => {
                m.display_name = op.value.as_ref().and_then(|v| v.as_str()).map(String::from);
            }
            ("replace" | "add", "name.givenName") => {
                m.given_name = op.value.as_ref().and_then(|v| v.as_str()).map(String::from);
            }
            ("replace" | "add", "name.familyName") => {
                m.family_name = op.value.as_ref().and_then(|v| v.as_str()).map(String::from);
            }
            ("replace" | "add", "") => {
                // Some IdPs send a single replace with no path and a JSON
                // object as value. Walk the object.
                if let Some(obj) = op.value.as_ref().and_then(|v| v.as_object()) {
                    if let Some(b) = obj.get("active").and_then(|v| v.as_bool()) { m.active = Some(b); }
                    if let Some(s) = obj.get("displayName").and_then(|v| v.as_str()) { m.display_name = Some(s.into()); }
                }
            }
            _ => { /* ignore unsupported ops; do not 400, per Okta compatibility */ }
        }
    }
    Ok(m)
}
```

### 4. The deactivation cascade

`scim/deactivation.rs`:

```rust
//! Atomic deactivation: in one Postgres transaction, walk every place
//! the user holds state and tear it down.
//!
//! Idempotency: re-running the cascade on an already-deactivated user
//! is a no-op. Each step uses safe-to-rerun primitives.

use moa_authz::outbox::enqueue_raw;
use moa_authz_schema::TupleOp;
use sqlx::Transaction;
use sqlx::Postgres;
use uuid::Uuid;

#[derive(Debug, thiserror::Error)]
pub enum CascadeError {
    #[error("db: {0}")]
    Db(#[from] sqlx::Error),
    #[error("authz: {0}")]
    Authz(#[from] moa_authz::AuthzError),
}

pub async fn cascade_deactivate_user(
    tx: &mut Transaction<'_, Postgres>,
    tenant_id: Uuid,
    user_id: Uuid,
) -> Result<(), CascadeError> {
    // 1. Flip the active flag (idempotent on second call).
    let res = sqlx::query(
        r#"
        UPDATE users
        SET active=false, deactivated_at=COALESCE(deactivated_at, NOW()),
            updated_at=NOW(), version=version+1
        WHERE id=$1 AND tenant_id=$2 AND active=true
        "#,
    )
    .bind(user_id).bind(tenant_id)
    .execute(&mut **tx)
    .await?;

    if res.rows_affected() == 0 {
        // Already inactive, or unknown user. Treat as no-op success.
        return Ok(());
    }

    // 2. Cancel active sessions owned by the user.
    //
    // Strategy: read the set of active session_ids, then mark each
    // cancelled via the existing session-cancel handler's underlying
    // SQL (a row update + an event-log entry, depending on schema).
    // We do not invoke the Restate handler from inside this tx; we
    // update the table directly. The actual Restate workflow cleanup
    // happens via a subsequent sweeper. P1.10 may emit the
    // session-cancel OCSF event from here.
    sqlx::query(
        r#"
        UPDATE sessions
        SET status='cancelled', updated_at=NOW(), completed_at=NOW()
        WHERE user_id=$1 AND tenant_id=$2 AND status NOT IN ('cancelled','completed','failed')
        "#,
    )
    .bind(user_id).bind(tenant_id)
    .execute(&mut **tx).await?;

    // 3. Revoke non-revoked API keys.
    let keys: Vec<(Uuid,)> = sqlx::query_as(
        "SELECT id FROM api_keys WHERE owner_user_id=$1 AND revoked_at IS NULL"
    )
    .bind(user_id).fetch_all(&mut **tx).await?;
    for (key_id,) in &keys {
        moa_auth_providers::api_keys::revoke(
            &mut **tx, *key_id, "deactivation_cascade", None
        ).await.map_err(|e| CascadeError::Db(sqlx::Error::Protocol(format!("api_keys::revoke: {e}"))))?;

        // Tear down the api_key's FGA owner edge.
        enqueue_raw(
            &mut **tx,
            TupleOp::Delete,
            &format!("user:{user_id}"),
            "owner",
            &format!("api_key:{key_id}"),
            Some(tenant_id),
        ).await?;
    }

    // 4. Tear down direct FGA tuples held by this user.
    //
    // We don't have a generic "find all tuples for subject" outside FGA
    // itself; FGA's ListUsers/ListObjects don't return arbitrary tuples
    // either. Strategy: write delete tuples for every relation we know
    // the user could hold, plus delete via a "shadow" join table for
    // anything user-specific we have explicit rows for. The outbox
    // poller's idempotent-on-OpenFGA behavior tolerates deleting tuples
    // that don't exist (returns 4xx, treated as success).
    //
    // Coverage matrix (relations a user can directly hold in schema v1/v2):
    let user_wire = format!("user:{user_id}");

    // tenant.{member, admin, billing_admin, scim_admin}: scim_admin is
    // for api_keys only.
    for relation in &["member", "admin", "billing_admin"] {
        enqueue_raw(&mut **tx, TupleOp::Delete, &user_wire, relation,
            &format!("tenant:{tenant_id}"), Some(tenant_id)).await?;
    }

    // workspace.* — we don't know which workspaces; instead, walk the
    // workspaces in this tenant and delete-tuple each. For tenants with
    // many workspaces this is wasteful; an alternative is to add a
    // `user_workspace_memberships` join table whenever workspace
    // tuples are issued and walk that. P2 may add this. For now,
    // tenant-wide walk:
    let workspaces: Vec<(Uuid,)> = sqlx::query_as(
        "SELECT id FROM workspaces WHERE tenant_id=$1"
    )
    .bind(tenant_id)
    .fetch_all(&mut **tx).await
    .unwrap_or_default();   // workspaces table may not yet exist in early dev
    for (ws_id,) in workspaces {
        for relation in &["member", "editor", "admin"] {
            enqueue_raw(&mut **tx, TupleOp::Delete, &user_wire, relation,
                &format!("workspace:{ws_id}"), Some(tenant_id)).await?;
        }
    }

    // agent.operator — agents owned/operated by this user need their
    // operator edge torn down. The agent rows themselves stay; an agent
    // without an operator is orphaned and a follow-up sweeper retires
    // them.
    let agents: Vec<(Uuid,)> = sqlx::query_as(
        "SELECT id FROM agents WHERE operator_user_id=$1"
    )
    .bind(user_id)
    .fetch_all(&mut **tx).await
    .unwrap_or_default();
    for (agent_id,) in agents {
        enqueue_raw(&mut **tx, TupleOp::Delete, &user_wire, "operator",
            &format!("agent:{agent_id}"), Some(tenant_id)).await?;
        sqlx::query("UPDATE agents SET operator_user_id=NULL, updated_at=NOW() WHERE id=$1")
            .bind(agent_id).execute(&mut **tx).await?;
    }

    // 5. Group memberships → FGA detach.
    sqlx::query("DELETE FROM scim_group_members WHERE user_id=$1").bind(user_id).execute(&mut **tx).await?;
    sqlx::query("DELETE FROM oidc_user_groups WHERE user_id=$1").bind(user_id).execute(&mut **tx).await?;

    // TODO P1.10: emit OCSF iam.user.disable event here with the full
    // cascade summary (n sessions cancelled, n keys revoked, n tuples deleted).

    Ok(())
}
```

### 5. Group handlers

`scim/groups.rs` — analogous to users, with the additional step of
maintaining FGA tuples via the configured group → relation mapping.
When `PATCH /Groups/<id>` adds or removes a member, enqueue the
corresponding tuple write/delete via the outbox. When a group is
deleted, walk its members and delete the tuples.

Keep the implementation tight; the patterns are identical to users.

### 6. Metadata endpoints

`scim/meta.rs` returns three static documents:

- `GET /scim/v2/ServiceProviderConfig` — declares supported features:
  `patch` true (RFC 7644 §3.5.2), `bulk` false, `filter` true (limited),
  `etag` true, `authenticationSchemes` lists "oauthbearertoken".
- `GET /scim/v2/ResourceTypes` — Lists User and Group resource types.
- `GET /scim/v2/Schemas` — Returns the SCIM core schemas. We ship
  `core:2.0:User` and `core:2.0:Group`; no enterprise extension.

Hard-code these as `serde_json::Value` constants in `scim/meta.rs`; the
contents are stable per the spec.

## Notes

- **Why hard PATCH semantics aren't fully implemented**: RFC 7644 §3.5.2
  is mature; enterprise IdPs use a tiny subset. P1.9 supports what Okta
  and Entra actually send. The "unknown ops ignored" behavior in
  `patch.rs` matches Okta's stated tolerance for partial implementations.
- **Cascade as one transaction, not many**: the cascade touches users,
  sessions, api_keys, agents, outbox, and group-membership tables. A
  failure mid-cascade with separate transactions would leave the user
  half-deprovisioned — exactly the failure mode P1.9 exists to prevent.
  One Postgres tx; either it all commits or nothing does.
- **Outbox deletes for FGA**: the outbox poller's idempotent-4xx
  handling means deleting a tuple that doesn't exist returns
  success. This is intentional — the cascade enqueues deletes for
  every relation a user *could* hold, regardless of whether they
  actually hold each. Wasteful in outbox rows, robust in correctness.
- **Workspace walk is O(n) on workspaces in the tenant**: large tenants
  may produce thousands of outbox rows per deactivation. For most
  workloads this is fine. If it becomes a problem, P2 can add a
  `user_workspace_memberships` join table that the cascade walks instead
  of `workspaces`.
- **Orphaned agents** (agents whose operator was deactivated): kept
  alive in P1.9; a follow-up sweeper (out of scope) retires them after
  N days. The reasoning is that an agent may be performing valuable
  ongoing work that survives a single user's deprovisioning — for
  example, a tenant-shared agent whose creator left the company.
- **Hard DELETE vs soft delete via active=false**: SCIM clients usually
  send PATCH active=false. DELETE is supported for compliance but is
  effectively the same operation plus a row removal. Neither path is
  GDPR hard-delete; that's a Phase 4 operation that scrubs PII
  across audit trails, lineage, etc.
- **Schema v2 bump for `scim_admin`**: this is the first real schema
  evolution in the auth pack. Old tuples written under model v1 still
  resolve against v1. New tuples (and the `scim_admin` relation) write
  under v2. The outbox `model_version` column distinguishes them in
  audit; in OpenFGA, the authorization_model_id is bumped per Write
  call. P1.10 will key OCSF events with the model_version so
  retrospective audits know which schema was in force.
- **SCIM auth via API key, not OIDC**: enterprise IdPs send a bearer
  token they generate on their side. SCIM "OAuth Bearer Token" mode is
  the standard; for MOA, a long-lived API key with `scim_admin` scope
  is the operationally simplest implementation. Rotate the key from
  the IdP's SCIM config when needed.
- **No bulk endpoint**: RFC 7644 §3.7. Bulk increases implementation
  cost significantly and few IdPs require it. Document as unsupported
  in `ServiceProviderConfig`; IdPs fall back to per-resource calls.
- **Tenant resolution**: the SCIM endpoint's tenant_id comes from the
  `scim_admin` tuple's object. A SCIM key cannot operate cross-tenant —
  one key per tenant per IdP.
