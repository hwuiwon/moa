# P1.2 — `moa-authz` Crate, Transactional Outbox, and Cross-Crate Traits

## Purpose

Build the production-grade FGA client and the Postgres-backed outbox that
keeps MOA's relational state and OpenFGA tuples consistent. Define the three
provider trait interfaces in `moa-core::traits` so downstream crates can
depend on the abstraction without pulling in any provider implementation.

End state:

- New crate `moa-authz` with a production FGA client (replaces the throwaway
  client in `moa-fga-bootstrap`).
- Per-crate sqlx migration creates an `authz_outbox` table with idempotency,
  status, attempts, and dead-letter tracking.
- `OutboxPoller` background task drains pending tuples to OpenFGA with
  bounded retry and exponential backoff; on giving up, rows move to
  `status='dead_letter'` and stop being polled but remain visible.
- `moa-core::traits` exposes `AuthProvider`, `TokenVaultProvider`,
  `AsyncAuthzProvider` traits with the types they depend on. No
  implementation lives here; only the contract.
- `moa-core::config` learns `[authz]` and `[authz.openfga]` sections, loaded
  via the existing `MOA__SECTION__KEY` env-var pattern.
- The orchestrator boots an `OutboxPoller` instance in `main.rs` against the
  same `PgPool` it already owns.

This prompt does not call `require_authz()` from any handler (that's P1.4)
and does not implement any provider impl (P1.6 for `LocalAuthProvider`, P1.7
for `Auth0AuthProvider`).

## Prerequisites

- P1.1 merged. OpenFGA boots with `make dev`; `moa-authz-schema` and
  `moa-fga-bootstrap` exist.
- A working `.env.fga` from `moa-fga-bootstrap` (or environment variables
  set equivalently) so the integration tests can run live.

### 2. Outbox migration

`crates/moa-authz/migrations/20260512000000_authz_outbox.up.sql`:

```sql
-- Transactional outbox for FGA tuple writes.
--
-- The flow: a handler that mutates Postgres state queues one or more tuple
-- ops into this table inside the same transaction. The OutboxPoller picks
-- up pending rows and applies them to OpenFGA. Idempotency_key prevents
-- duplicate application even if the poller crashes mid-batch.
--
-- Status transitions: pending -> in_flight -> succeeded | pending (retry)
-- After max_attempts, in_flight -> dead_letter. Dead-letter rows are not
-- retried; they require human intervention.

CREATE TABLE authz_outbox (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    idempotency_key TEXT        NOT NULL UNIQUE,
    op              TEXT        NOT NULL CHECK (op IN ('write', 'delete')),
    -- The tuple payload in OpenFGA wire format: { user, relation, object }.
    -- We store the wire format (not the typed TupleKey) so we don't have to
    -- migrate this row on every Rust-side type change.
    tuple_user      TEXT        NOT NULL,
    tuple_relation  TEXT        NOT NULL,
    tuple_object    TEXT        NOT NULL,
    model_version   INTEGER     NOT NULL,
    status          TEXT        NOT NULL DEFAULT 'pending'
                                CHECK (status IN ('pending', 'in_flight', 'succeeded', 'dead_letter')),
    attempts        INTEGER     NOT NULL DEFAULT 0,
    last_error      TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    next_attempt_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    -- Optional: which tenant this op concerns; populated by the caller for
    -- per-tenant observability and dead-letter triage.
    tenant_id       UUID
);

-- Single hot index: the poller's main query is "WHERE status='pending' AND
-- next_attempt_at <= NOW() ORDER BY next_attempt_at LIMIT N FOR UPDATE SKIP LOCKED".
CREATE INDEX idx_authz_outbox_pending
    ON authz_outbox(next_attempt_at)
    WHERE status = 'pending';

CREATE INDEX idx_authz_outbox_dead_letter
    ON authz_outbox(updated_at DESC)
    WHERE status = 'dead_letter';

CREATE INDEX idx_authz_outbox_tenant
    ON authz_outbox(tenant_id, status)
    WHERE tenant_id IS NOT NULL;
```

### 4. FGA client (production)

`crates/moa-authz/src/client.rs`:

```rust
//! Production FGA client. Differences from `moa-fga-bootstrap::http`:
//! - Reusable, holds a connection pool via `reqwest::Client`.
//! - Strongly typed errors via `AuthzError`.
//! - `Check`, `BatchCheck`, `ListObjects`, `Read`, `Write`, `WriteWithIdempotency`.
//! - Logs structured request metadata via `tracing`.

use crate::error::AuthzError;
use moa_authz_schema::{TupleKey, TupleOp};
use reqwest::Client;
use serde::{Deserialize, Serialize};
use serde_json::json;
use std::sync::Arc;
use std::time::Duration;

#[derive(Clone)]
pub struct FgaClient {
    inner: Arc<FgaInner>,
}

struct FgaInner {
    base: String,
    http: Client,
    token: String,
    store_id: String,
    model_id: String,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct FgaConfig {
    pub url: String,
    pub preshared_key: String,
    pub store_id: String,
    pub model_id: String,
    /// Per-request HTTP timeout.
    #[serde(default = "default_timeout_ms")]
    pub timeout_ms: u64,
}

fn default_timeout_ms() -> u64 { 5000 }

impl FgaClient {
    pub fn new(cfg: FgaConfig) -> Result<Self, AuthzError> {
        let http = Client::builder()
            .timeout(Duration::from_millis(cfg.timeout_ms))
            .build()
            .map_err(AuthzError::Transport)?;
        Ok(Self {
            inner: Arc::new(FgaInner {
                base: cfg.url.trim_end_matches('/').to_string(),
                http,
                token: cfg.preshared_key,
                store_id: cfg.store_id,
                model_id: cfg.model_id,
            }),
        })
    }

    pub fn store_id(&self) -> &str { &self.inner.store_id }
    pub fn model_id(&self) -> &str { &self.inner.model_id }

    #[tracing::instrument(skip(self), fields(store_id = %self.inner.store_id))]
    pub async fn check(
        &self,
        user: &str,
        relation: &str,
        object: &str,
    ) -> Result<bool, AuthzError> {
        let r = self.inner.http
            .post(format!("{}/stores/{}/check", self.inner.base, self.inner.store_id))
            .bearer_auth(&self.inner.token)
            .json(&json!({
                "authorization_model_id": self.inner.model_id,
                "tuple_key": { "user": user, "relation": relation, "object": object },
            }))
            .send()
            .await?;
        let status = r.status();
        if !status.is_success() {
            return Err(AuthzError::HttpError {
                status: status.as_u16(),
                body: r.text().await.unwrap_or_default(),
            });
        }
        let v: serde_json::Value = r.json().await?;
        v.get("allowed").and_then(|b| b.as_bool())
            .ok_or_else(|| AuthzError::Ambiguous("Check missing 'allowed'".into()))
    }

    #[tracing::instrument(skip(self, items), fields(store_id = %self.inner.store_id, n = items.len()))]
    pub async fn batch_check(
        &self,
        items: &[(String, String, String)],
    ) -> Result<Vec<bool>, AuthzError> {
        let checks: Vec<serde_json::Value> = items.iter().enumerate().map(|(i, (u, r, o))| {
            json!({
                "tuple_key": { "user": u, "relation": r, "object": o },
                "correlation_id": format!("c{i}"),
            })
        }).collect();

        let r = self.inner.http
            .post(format!("{}/stores/{}/batch-check", self.inner.base, self.inner.store_id))
            .bearer_auth(&self.inner.token)
            .json(&json!({
                "authorization_model_id": self.inner.model_id,
                "checks": checks,
            }))
            .send().await?;
        let status = r.status();
        if !status.is_success() {
            return Err(AuthzError::HttpError {
                status: status.as_u16(),
                body: r.text().await.unwrap_or_default(),
            });
        }
        let v: serde_json::Value = r.json().await?;
        let map = v.get("result").or_else(|| v.get("results"))
            .and_then(|x| x.as_object())
            .ok_or_else(|| AuthzError::Ambiguous("BatchCheck missing result".into()))?;
        let mut out = Vec::with_capacity(items.len());
        for i in 0..items.len() {
            let entry = map.get(&format!("c{i}"))
                .ok_or_else(|| AuthzError::Ambiguous(format!("BatchCheck missing c{i}")))?;
            out.push(entry.get("allowed").and_then(|b| b.as_bool()).unwrap_or(false));
        }
        Ok(out)
    }

    /// Apply a single tuple op. Caller is responsible for idempotency at the
    /// caller's layer (the outbox poller). This client does not retry.
    #[tracing::instrument(skip(self, tuple), fields(op = %op))]
    pub async fn apply(
        &self,
        op: TupleOp,
        tuple: &TupleKey,
    ) -> Result<(), AuthzError> {
        let wire = json!({
            "user":     tuple.user_wire(),
            "relation": tuple.relation.to_string(),
            "object":   tuple.object_wire(),
        });
        let body = match op {
            TupleOp::Write => json!({
                "authorization_model_id": self.inner.model_id,
                "writes": { "tuple_keys": [wire] },
            }),
            TupleOp::Delete => json!({
                "authorization_model_id": self.inner.model_id,
                "deletes": { "tuple_keys": [wire] },
            }),
        };

        let r = self.inner.http
            .post(format!("{}/stores/{}/write", self.inner.base, self.inner.store_id))
            .bearer_auth(&self.inner.token)
            .json(&body)
            .send().await?;
        let status = r.status();
        if status.is_success() {
            return Ok(());
        }
        // OpenFGA returns 4xx for "tuple already exists" / "tuple does not exist".
        // For the outbox flow these are idempotent successes — the poller's
        // job is to converge state, and the desired state is already met.
        let body_text = r.text().await.unwrap_or_default();
        if is_idempotent_409(status.as_u16(), &body_text) {
            tracing::debug!(status = %status, "FGA returned idempotent 4xx; treating as success");
            return Ok(());
        }
        Err(AuthzError::HttpError { status: status.as_u16(), body: body_text })
    }
}

/// OpenFGA returns:
///   400 with error code `write_failed_due_to_invalid_input` and message
///   "tuple already exists" on duplicate write
///   400 with message "tuple does not exist" on delete of missing tuple
/// Both are no-op-success for an outbox poller.
fn is_idempotent_409(status: u16, body: &str) -> bool {
    if status != 400 && status != 409 {
        return false;
    }
    let lc = body.to_lowercase();
    lc.contains("already exists") || lc.contains("does not exist")
}
```

### 5. Outbox enqueue + poller

`crates/moa-authz/src/outbox.rs`:

```rust
//! Outbox row management. Enqueue is called from inside the caller's
//! Postgres transaction; the poller reads/updates independently.

use crate::error::AuthzError;
use moa_authz_schema::{TupleKey, TupleOp, MODEL_VERSION};
use sqlx::PgExecutor;
use uuid::Uuid;

/// Enqueue a tuple op into the outbox. Idempotent: if `idempotency_key`
/// already exists, the existing row is left untouched (no error).
///
/// Must be called inside a transaction together with the caller's state mutation.
pub async fn enqueue<'e, E: PgExecutor<'e>>(
    exec: E,
    op: TupleOp,
    tuple: &TupleKey,
    tenant_id: Option<Uuid>,
) -> Result<(), AuthzError> {
    let key = tuple.idempotency_key(op, MODEL_VERSION);
    sqlx::query(
        r#"
        INSERT INTO authz_outbox
            (idempotency_key, op, tuple_user, tuple_relation, tuple_object, model_version, tenant_id)
        VALUES ($1, $2, $3, $4, $5, $6, $7)
        ON CONFLICT (idempotency_key) DO NOTHING
        "#,
    )
    .bind(&key)
    .bind(op.to_string())
    .bind(tuple.user_wire())
    .bind(tuple.relation.to_string())
    .bind(tuple.object_wire())
    .bind(MODEL_VERSION as i32)
    .bind(tenant_id)
    .execute(exec)
    .await?;
    Ok(())
}

#[derive(Debug, Clone)]
pub(crate) struct OutboxRow {
    pub id: Uuid,
    pub idempotency_key: String,
    pub op: String, // "write" | "delete"
    pub tuple_user: String,
    pub tuple_relation: String,
    pub tuple_object: String,
    pub attempts: i32,
}
```

`crates/moa-authz/src/poller.rs`:

```rust
//! Background poller that drains the outbox to OpenFGA.

use crate::client::FgaClient;
use crate::error::AuthzError;
use crate::outbox::OutboxRow;
use serde_json::json;
use sqlx::PgPool;
use std::time::Duration;
use tokio::sync::oneshot;
use tokio::time::sleep;

/// Tunable poller configuration.
#[derive(Debug, Clone)]
pub struct PollerConfig {
    pub batch_size: usize,
    pub poll_interval: Duration,
    pub max_attempts: i32,
    /// Backoff schedule for retries: attempt N waits for `base * 2^(N-1)`
    /// up to `cap`.
    pub backoff_base: Duration,
    pub backoff_cap: Duration,
}

impl Default for PollerConfig {
    fn default() -> Self {
        Self {
            batch_size: 64,
            poll_interval: Duration::from_millis(500),
            max_attempts: 8,
            backoff_base: Duration::from_millis(200),
            backoff_cap: Duration::from_secs(60),
        }
    }
}

pub struct OutboxPoller {
    pool: PgPool,
    client: FgaClient,
    cfg: PollerConfig,
}

impl OutboxPoller {
    pub fn new(pool: PgPool, client: FgaClient, cfg: PollerConfig) -> Self {
        Self { pool, client, cfg }
    }

    /// Spawn the poller as a tokio task. Returns a shutdown handle.
    pub fn spawn(self) -> PollerHandle {
        let (tx, mut rx) = oneshot::channel::<()>();
        let task = tokio::spawn(async move {
            loop {
                tokio::select! {
                    biased;
                    _ = &mut rx => {
                        tracing::info!("outbox poller received shutdown");
                        break;
                    }
                    _ = sleep(self.cfg.poll_interval) => {}
                }
                if let Err(e) = self.tick().await {
                    tracing::error!(error = %e, "outbox poller tick failed");
                }
            }
        });
        PollerHandle { shutdown: Some(tx), task }
    }

    /// Single drain pass. Public for tests.
    pub async fn tick(&self) -> Result<usize, AuthzError> {
        // Claim up to `batch_size` pending rows with `FOR UPDATE SKIP LOCKED`
        // so multiple poller instances do not collide.
        let mut tx = self.pool.begin().await?;
        let claimed: Vec<OutboxRow> = sqlx::query_as(
            r#"
            SELECT id, idempotency_key, op, tuple_user, tuple_relation, tuple_object, attempts
            FROM authz_outbox
            WHERE status = 'pending'
              AND next_attempt_at <= NOW()
            ORDER BY next_attempt_at
            LIMIT $1
            FOR UPDATE SKIP LOCKED
            "#,
        )
        .bind(self.cfg.batch_size as i64)
        .fetch_all(&mut *tx)
        .await?;

        if claimed.is_empty() {
            tx.commit().await?;
            return Ok(0);
        }

        let ids: Vec<uuid::Uuid> = claimed.iter().map(|r| r.id).collect();
        sqlx::query("UPDATE authz_outbox SET status='in_flight', updated_at=NOW() WHERE id = ANY($1)")
            .bind(&ids)
            .execute(&mut *tx)
            .await?;
        tx.commit().await?;

        let mut applied = 0usize;
        for row in claimed {
            match self.apply_row(&row).await {
                Ok(()) => {
                    sqlx::query("UPDATE authz_outbox SET status='succeeded', updated_at=NOW() WHERE id=$1")
                        .bind(row.id)
                        .execute(&self.pool)
                        .await?;
                    applied += 1;
                }
                Err(e) => {
                    let next_attempts = row.attempts + 1;
                    if next_attempts >= self.cfg.max_attempts {
                        tracing::error!(
                            id = %row.id,
                            key = %row.idempotency_key,
                            attempts = next_attempts,
                            error = %e,
                            "outbox row exhausted retries; moving to dead_letter"
                        );
                        sqlx::query(
                            r#"
                            UPDATE authz_outbox
                            SET status='dead_letter', attempts=$2, last_error=$3, updated_at=NOW()
                            WHERE id=$1
                            "#,
                        )
                        .bind(row.id)
                        .bind(next_attempts)
                        .bind(format!("{}", e))
                        .execute(&self.pool)
                        .await?;
                    } else {
                        let backoff = self.backoff_for(next_attempts);
                        tracing::warn!(
                            id = %row.id,
                            key = %row.idempotency_key,
                            attempts = next_attempts,
                            backoff_ms = backoff.as_millis() as u64,
                            error = %e,
                            "outbox row failed; backing off"
                        );
                        sqlx::query(
                            r#"
                            UPDATE authz_outbox
                            SET status='pending',
                                attempts=$2,
                                last_error=$3,
                                next_attempt_at=NOW() + ($4 || ' milliseconds')::INTERVAL,
                                updated_at=NOW()
                            WHERE id=$1
                            "#,
                        )
                        .bind(row.id)
                        .bind(next_attempts)
                        .bind(format!("{}", e))
                        .bind(backoff.as_millis().to_string())
                        .execute(&self.pool)
                        .await?;
                    }
                }
            }
        }

        Ok(applied)
    }

    async fn apply_row(&self, row: &OutboxRow) -> Result<(), AuthzError> {
        // Reconstruct the wire tuple. We use the *_wire fields directly to
        // avoid coupling poll-time logic to Rust-side enum changes.
        let body = match row.op.as_str() {
            "write" => json!({
                "authorization_model_id": self.client.model_id(),
                "writes": { "tuple_keys": [{
                    "user": row.tuple_user,
                    "relation": row.tuple_relation,
                    "object": row.tuple_object,
                }]},
            }),
            "delete" => json!({
                "authorization_model_id": self.client.model_id(),
                "deletes": { "tuple_keys": [{
                    "user": row.tuple_user,
                    "relation": row.tuple_relation,
                    "object": row.tuple_object,
                }]},
            }),
            other => return Err(AuthzError::Ambiguous(format!("unknown op: {other}"))),
        };
        self.client.apply_raw(body).await
    }

    fn backoff_for(&self, attempt: i32) -> Duration {
        let pow = (attempt as u32).saturating_sub(1).min(20);
        let mult = 1u64 << pow;
        let ms = (self.cfg.backoff_base.as_millis() as u64).saturating_mul(mult);
        Duration::from_millis(ms).min(self.cfg.backoff_cap)
    }
}

pub struct PollerHandle {
    shutdown: Option<oneshot::Sender<()>>,
    task: tokio::task::JoinHandle<()>,
}

impl PollerHandle {
    pub async fn shutdown(mut self) {
        if let Some(tx) = self.shutdown.take() {
            let _ = tx.send(());
        }
        let _ = self.task.await;
    }
}
```

### 7. Cross-crate trait surface in `moa-core::traits`

Add `crates/moa-core/src/traits/auth.rs` (a new file in the existing
`traits/` module). Reference `docs/architecture/type-placement.md` if review

```rust
//! Authentication, authorization-decision, and token-vault trait surfaces.
//!
//! These traits live in `moa-core::traits` so downstream crates can depend
//! on the *contract* (e.g., `moa-edge` depends on `dyn AuthProvider`) without
//! pulling in any provider implementation crate. The implementations live
//! elsewhere:
//!
//! - `moa-auth-providers` (P1.6): local + null + builtin defaults

// ---------- Common identity types ----------

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum IdentityType {
    User,
    Agent,
    Service,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Identity {
    pub identity_type: IdentityType,
    pub id: Uuid,
    pub tenant_id: Uuid,
    /// Set when authentication used an API key. Otherwise None.
    pub api_key_id: Option<Uuid>,
    /// Set when an agent is acting on behalf of a user (delegation).
    pub acting_on_behalf_of: Option<Uuid>,
}

// ---------- AuthProvider ----------

#[derive(Debug)]
pub enum Credential {
    ApiKey(String),
    BearerJwt(String),
}

#[derive(Debug, Error)]
pub enum AuthError {
    #[error("invalid credential format")]
    InvalidFormat,
    #[error("credential rejected by provider")]
    Rejected,
    #[error("credential expired")]
    Expired,
    #[error("provider unavailable: {0}")]
    Unavailable(String),
    #[error("provider not configured for this credential type")]
    NotConfigured,
    #[error("internal: {0}")]
    Internal(String),
}

#[async_trait]
pub trait AuthProvider: Send + Sync {
    /// Resolve a credential to an Identity. Returns AuthError on any
    /// failure; never panics. Implementations must be safe to call
    /// concurrently.
    async fn authenticate(&self, credential: &Credential) -> Result<Identity, AuthError>;

    /// Short stable name for logs and metrics. e.g., "local", "auth0", "oidc".
    fn name(&self) -> &'static str;
}

// ---------- TokenVaultProvider ----------

/// Wraps a third-party access token. Implementations must zeroize on drop
/// where possible; treat this as sensitive material throughout.
#[derive(Debug, Clone)]
pub struct VaultToken {
    pub access_token: secrecy::SecretString,
    pub expires_at: Option<DateTime<Utc>>,
    pub scopes: Vec<String>,
}

#[derive(Debug, Error)]
pub enum TokenVaultError {
    #[error("vault not configured")]
    NotConfigured,
    #[error("connection not linked for this user")]
    NotLinked,
    #[error("vault unavailable: {0}")]
    Unavailable(String),
    #[error("internal: {0}")]
    Internal(String),
}

#[async_trait]
pub trait TokenVaultProvider: Send + Sync {
    /// Retrieve a current access token for `(user_id, connection_name)`.
    /// Implementations should refresh transparently if their underlying
    /// vault supports it.
    async fn get_token(
        &self,
        user_id: Uuid,
        connection_name: &str,
    ) -> Result<VaultToken, TokenVaultError>;

    /// List connection names that `user_id` has linked.
    async fn list_connections(&self, user_id: Uuid) -> Result<Vec<String>, TokenVaultError>;

    fn name(&self) -> &'static str;
}

// ---------- AsyncAuthzProvider ----------

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ApprovalRequest {
    pub session_id: Uuid,
    /// The user whose decision we are waiting on. In delegation flows this
    /// is `acting_on_behalf_of`, not the agent's user_id.
    pub deciding_user_id: Uuid,
    /// Human-readable one-line summary, shown in the approval UI.
    pub action_summary: String,
    /// Full action JSON: tool name, parameters, target resource, etc.
    pub action_details: serde_json::Value,
    /// Restate awakeable id; resolving this unblocks the workflow body.
    pub awakeable_id: String,
    pub timeout: Duration,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ApprovalHandle {
    pub id: Uuid,
    pub awakeable_id: String,
    /// Free-form provider metadata (e.g., Auth0 CIBA `auth_req_id`).
    #[serde(default)]
    pub provider_specific: serde_json::Value,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case", tag = "outcome")]
pub enum ApprovalDecision {
    Approved,
    Denied { reason: Option<String> },
    Timeout,
}

#[derive(Debug, Error)]
pub enum AsyncAuthzError {
    #[error("not configured")]
    NotConfigured,
    #[error("provider unavailable: {0}")]
    Unavailable(String),
    #[error("internal: {0}")]
    Internal(String),
}

#[async_trait]
pub trait AsyncAuthzProvider: Send + Sync {
    /// Initiate an out-of-band approval. Does not block; returns immediately
    /// with a handle the workflow uses to resolve later.
    async fn request_approval(
        &self,
        request: ApprovalRequest,
    ) -> Result<ApprovalHandle, AsyncAuthzError>;

    /// The implementation is responsible for resolving the awakeable when
    /// the user decides. This method exists for providers that need a
    /// poll-driven model; the builtin/Auth0 impls leave it as the default
    /// noop and resolve via their own callback path.
    async fn poll_decision(
        &self,
        _handle: &ApprovalHandle,
    ) -> Result<Option<ApprovalDecision>, AsyncAuthzError> {
        Ok(None)
    }

    fn name(&self) -> &'static str;
}
```

```rust
//! `[authz]` and `[authz.openfga]` config sections.
//!
//! Env-var equivalents follow the MOA__SECTION__KEY convention:
//!   MOA__AUTHZ__ENGINE=openfga
//!   MOA__AUTHZ__OPENFGA__URL=http://localhost:8081

#[derive(Debug, Clone, Serialize, Deserialize)]

    pub model_id: String,
```

```rust
//! Outbox enqueue + poller behavior. Unit-test the SQL surface.
//! Live FGA tests are separate and `#[ignore]`-gated.

use moa_authz::{enqueue, FgaClient, FgaConfig, OutboxPoller, PollerConfig};
use moa_authz_schema::{ObjectType, Relation, TupleKey, TupleOp, UserType};
use sqlx::PgPool;
use uuid::Uuid;

#[sqlx::test(migrations = "./migrations")]
async fn enqueue_is_idempotent_on_same_key(pool: PgPool) {
    let user_id = Uuid::new_v4();
    let ws_id = Uuid::new_v4();
    let t = TupleKey::new(
        UserType::User, user_id, Relation::Editor,
        ObjectType::Workspace, ws_id,
    );

    enqueue(&pool, TupleOp::Write, &t, None).await.unwrap();
    enqueue(&pool, TupleOp::Write, &t, None).await.unwrap();
    enqueue(&pool, TupleOp::Write, &t, None).await.unwrap();

    let count: i64 = sqlx::query_scalar("SELECT COUNT(*) FROM authz_outbox")
        .fetch_one(&pool).await.unwrap();
    assert_eq!(count, 1, "three enqueues of the same key must produce exactly one row");
}
```

`crates/moa-authz/tests/poller_live.rs`:

```rust
//! Live poller test against a running OpenFGA + Postgres.
//! Gated behind MOA_RUN_LIVE_OPENFGA_TESTS=1 per AGENTS.md.

use moa_authz::{enqueue, FgaClient, FgaConfig, OutboxPoller, PollerConfig};
use moa_authz_schema::{ObjectType, Relation, TupleKey, TupleOp, UserType};
use sqlx::PgPool;
use std::time::Duration;
use uuid::Uuid;

fn fga_from_env() -> FgaConfig {
    FgaConfig {
        url: std::env::var("MOA_OPENFGA_URL").expect("MOA_OPENFGA_URL"),
        preshared_key: std::env::var("MOA_OPENFGA_PRESHARED_KEY").expect("MOA_OPENFGA_PRESHARED_KEY"),
        store_id: std::env::var("MOA_OPENFGA_STORE_ID").expect("MOA_OPENFGA_STORE_ID"),
        model_id: std::env::var("MOA_OPENFGA_MODEL_ID").expect("MOA_OPENFGA_MODEL_ID"),
        timeout_ms: 5000,
    }
}

#[sqlx::test(migrations = "./migrations")]
#[ignore = "requires MOA_RUN_LIVE_OPENFGA_TESTS=1 and live OpenFGA"]
async fn poller_drains_write_to_fga(pool: PgPool) {
    if std::env::var("MOA_RUN_LIVE_OPENFGA_TESTS").as_deref() != Ok("1") {
        return;
    }

    let tenant_id = Uuid::new_v4();
    let user_id = Uuid::new_v4();

    // Write `user is member of tenant`.
    let t = TupleKey::new(
        UserType::User, user_id, Relation::Member,
        ObjectType::Tenant, tenant_id,
    );
    enqueue(&pool, TupleOp::Write, &t, Some(tenant_id)).await.unwrap();

    let client = FgaClient::new(fga_from_env()).unwrap();
    let poller = OutboxPoller::new(pool.clone(), client.clone(), PollerConfig::default());

    let drained = poller.tick().await.unwrap();
    assert_eq!(drained, 1, "exactly one row drained");

    // Verify FGA sees the tuple.
    let allowed = client.check(
        &format!("user:{user_id}"),
        "member",
        &format!("tenant:{tenant_id}"),
    ).await.unwrap();
    assert!(allowed, "tuple write should make user a tenant member");

    let status: String = sqlx::query_scalar(
        "SELECT status FROM authz_outbox WHERE id IS NOT NULL LIMIT 1"
    ).fetch_one(&pool).await.unwrap();
    assert_eq!(status, "succeeded");

    // Cleanup: enqueue + drain the delete so the FGA store is clean.
    enqueue(&pool, TupleOp::Delete, &t, Some(tenant_id)).await.unwrap();
    poller.tick().await.unwrap();
}
```

- [ ] `cargo build --workspace` succeeds with zero warnings.
- [ ] `cargo hakari verify` passes.
- [ ] `cargo test -p moa-authz outbox_basic` passes; both assertions pin
      specific row counts (not `is_ok()`).
- [ ] `cargo test -p moa-core traits::auth` compiles trivial dyn-trait
      smoke tests; the traits are object-safe.
- [ ] `make dev` boots a working orchestrator that logs "authz outbox
      poller started" exactly once on startup.
- [ ] Manually enqueueing a tuple via `psql` (against `authz_outbox`) and
      observing it transition to `status='succeeded'` within
      `poll_interval * 2` proves the live poller drains.
- [ ] `MOA_RUN_LIVE_OPENFGA_TESTS=1 cargo test -p moa-authz -- --ignored`
      passes against a running stack.
- [ ] `psql -c "SELECT status, COUNT(*) FROM authz_outbox GROUP BY status"`
      returns expected statuses (`pending` / `in_flight` / `succeeded` /
      `dead_letter`) — manually crafted bad tuples should move to
      `dead_letter` after `max_attempts` retries.
- [ ] Killing the orchestrator (Ctrl-C) cleanly stops the poller; logs
      show "outbox poller received shutdown".
- [ ] Stale `in_flight` rows from a crashed poller are *not* automatically
      retried on next boot — this is an acceptance criterion documented in
      the runbook (P1.10 territory). Operators must `UPDATE authz_outbox
      SET status='pending' WHERE status='in_flight'` after an unclean
      shutdown.

## Notes

- **Why `FOR UPDATE SKIP LOCKED`**: multiple orchestrator replicas will run
  multiple pollers in production. `FOR UPDATE SKIP LOCKED` is the standard
  Postgres pattern for non-conflicting work queues. Each poller claims its
  own non-overlapping batch.
- **Why we don't reset `in_flight` rows on boot**: an `in_flight` row may
  be mid-application by another live poller in a multi-replica deployment.
  Auto-resetting would create a duplicate-application risk. P1.10's runbook
  will document the manual reset procedure.
- **Idempotency at two layers**: outbox enqueue uses `ON CONFLICT DO
  NOTHING` against `idempotency_key`. OpenFGA's `Write` API is also
  idempotent at the tuple-key level (duplicate writes return 400 with
  "already exists" which we treat as success). Both layers must hold; the
  outbox covers the database side, OpenFGA covers the FGA side.
- **Why traits live in `moa-core::traits`** and not in `moa-auth-providers`:
  see `docs/architecture/type-placement.md`. Trait contracts go in
  `moa-core::traits` (joining `CredentialVault`), implementations go in
  separate crates. `moa-edge` (P1.3) depends only on `moa-core::traits`,
  not on any provider crate.
- **Dead-letter handling**: rows in `status='dead_letter'` are visible but
  not retried. Operators triage manually. A future prompt may add a CLI
  command (`moa-cli authz dead-letter list/retry/dismiss`); not in scope
  for P1.2.
- **No DLQ alert wiring in this prompt**: the auth pack does not yet have
  an alerting target. The `last_error` column is the only output. P1.10
  may add Prometheus counters / OCSF events when dead-lettering occurs.
- **Why store the wire form**, not the TupleKey, in the outbox row:
  decoupling. Rust-side enum changes (e.g., adding a new relation) should
  not require migrating in-flight outbox rows. The wire form is what
  OpenFGA stores; mirror it.
- **`secrecy::SecretString`**: pulled in to type-protect the access_token
  field. If `moa-core` does not yet depend on `secrecy`, add it to
  workspace deps. Implementations zeroize on drop where possible.
- **`OpenFgaConfig` and `FgaConfig` look similar but are distinct types**:
  the config crate version is the parsed config-file shape;
  `moa-authz::FgaConfig` is the runtime client constructor. Keep them
  separate so config-format changes do not propagate into the client API
  unnecessarily.

- `moa-core::traits::{AuthProvider, TokenVaultProvider, AsyncAuthzProvider,
